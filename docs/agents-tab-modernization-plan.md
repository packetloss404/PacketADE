# Agents Tab — Modernization Review & Lift Plan

_Generated by a 40-agent review workflow (314 findings: 59 high / 140 medium / 115 low). Held against the freshly-polished Workspaces tab as the design bar._

## Verdict

The Agents tab sits a clear tier below the freshly-polished Workspaces bar — not because it lacks features (it is actually richer mid-conversation) but because it reads as an accretion of independently hand-built widgets that never got a unifying pass. The through-line is "no shared source of truth": type sizes drift off-scale in ~50 places (text-[9.5px]/[10.5px]/[8px]/[13px]), primary actions are thin green outlines instead of the confident filled recipe, list selection misuses accent-green, transitions/motion are absent, and every popover/select/checkbox/tooltip is reinvented per-feature. On top of the cosmetic gap there is a dangerous cluster of real correctness bugs: the obvious "close" X permanently deletes a conversation, context-usage math is wrong three different ways, several failure paths leave permanently-spinning streaming bubbles, and the @/slash popovers can fire accidental sends. The lift is large but mostly mechanical: snap to tokens, adopt the filled-primary + purple-selection recipes, build ~6 missing primitives, consolidate the triplicated status bars, close the launch↔chat option asymmetry, and fix the bug cluster.

## Recurring themes

- Off-scale typography everywhere (9.5/10.5/8/13/12px literals) vs the disciplined 12/11/10/9 scale Workspaces holds — the most pervasive mechanical '2nd-rate' tell
- Flat action hierarchy: pivotal Approve/Apply/Launch/Send actions use thin green outlines instead of the filled accent-green/20→/30 primary recipe; transition-colors missing on the buttons users touch most
- accent-green is overloaded (primary action + list selection + live status); contract reserves purple for selection — sidebar/diff/file rows ignore this
- Reinvention over primitives: no Tooltip/Spinner/Toast/Popover/Badge/Checkbox/SegmentedControl; native alert()/select/checkbox leak in; Button(1 use)/Input(0 uses) are dead
- Redundant chrome: three stacked status strips (SessionHealthBar + AgentStatusBar + header line + ContextUsageRing) duplicate model/ctx/cost/branch and double-poll git
- Launch↔chat asymmetry: mode/permission/MCP/memory/reasoning-effort only exist mid-conversation, so the launcher feels feature-thin at the moment that matters
- Missing states & motion: empty/loading/error states are bare or wrong; popovers teleport in, collapsibles snap, modals don't fade — no entrance animation anywhere
- Homegrown diff & card systems: two diff engines, full-line coloring, no line numbers, non-interleaved hunks; 5 inline cards with 5 different surfaces
- Correctness debt: data-loss on close/delete/restore, wrong context math, stuck streaming bubbles, accidental sends from mention popovers

## Top priorities (ordered, highest leverage first)

1. Kill the data-loss traps: make the chat-pane Close (X) non-destructive (selectConversation(null)) and gate Delete + Restore behind a confirm Modal
2. Global token pass: snap all off-scale type (9.5/10.5/8/13/12px) to 12/11/10/9, standardize radii to rounded (rounded-lg=modals only), and replace arbitrary token opacities
3. Fix the action hierarchy: filled accent-green/20→/30 primary recipe for Send/Launch/Approve/Apply/plan+spec CTAs, and add transition-colors to every approve/deny/cancel/panel button
4. Add focus-within:border-accent-green to both composers and switch list selection from green to the accent-purple recipe (free green for action/live only)
5. Fix correctness bugs in user-facing surfaces: whitespace-pre-wrap user messages, context-usage math (single source, latest-turn occupancy incl cache), stuck streaming bubbles (failTurn), voice transcript dup, reviewed-diff badge, and the @/slash accidental-send + index-clamp bugs
6. Build the missing primitives (Tooltip, Spinner, Toast, Popover, Badge, EmptyState, Checkbox) and route alert()/native select/native checkbox/console.warn errors and the worst hand-rolled popovers through them
7. Collapse the three stacked status strips into one bar, dedupe git polling, and align all three pane headers to a shared h-[33px] baseline
8. Close the launch↔chat asymmetry: surface mode (first-class segmented), permission mode, plan mode, memory-context, MCP, and a new reasoning-effort control in the composer
9. Unify the card system (tool + rich cards on one BaseToolCard) and rebuild the diff viewer (interleaved rows, line-number gutter, background-only tint, single shared engine, syntax highlight)
10. Add a motion pass (popover fade+scale entrance, collapsible height/opacity, Modal/overlay fade) and an a11y pass (Modal focus-trap, Dropdown keyboard nav, composer combobox ARIA, tablist/listbox semantics, aria-pressed/current), all motion-reduce gated
11. Refactor createApiConversation to a typed options object and extract patchConversation/failTurn helpers; make module-load hydration an explicit init()
12. Unify the agent-identity color map across Agents and Workspaces (shared src/lib/agentColors.ts) and snap 'running' status to one color

## New / surfaced options ("have the options")

### Reasoning-effort / thinking-budget control (Low/Med/High/Max) beside the model
No reasoning-effort/extended-thinking/temperature control exists anywhere — only a read-only heuristic speed pill, plus a hidden Alt+. hack that secretly swaps models. Claude extended-thinking and OpenAI/Codex reasoning_effort are table-stakes; add reasoningEffort to AgentConversation and a segmented toggle, plumbed through the launch payload.

### MCP server picker in the launch composer
MCP can only be chosen mid-conversation and is explicitly relaunch-gated ('sidecar can't hot-swap'), so the one place it can take effect at session start — the launcher — has no picker. Add a multi-select pill reusing mcpStore.

### Surface permission-mode, plan-mode, memory-context, transcript density at launch
These live only in HeaderActions mid-conversation, so users can't configure how the agent behaves before the first (often destructive) turn — the dominant 'feature-thin at launch' impression vs Cursor/Claude Code.

### First-class Mode segmented control out of the Advanced accordion
agent/ask/manual/plan is the most consequential behavioral switch yet is buried in a collapsed-by-default accordion; best-in-class makes it a primary control beside the model.

### General file/folder/URL attachments and @-folder/@-symbol context
Attachments are hard-limited to images (paste filters image/*, placeholder says 'images'); @ inserts file paths only. No way to attach arbitrary files, folders, URLs, or reference a folder/symbol — context-poor vs Cursor.

### Model context-window + pricing in the picker, plus favorites/pinning
ApiModel is only {label,value}; both dropdowns render bare labels with no way to compare cost/context budget and no pinning. Add contextWindow/pricing meta columns (mirror the Ollama GB pattern).

### Editable system-prompt / rules / AGENTS.md surface + inline profile create/edit
System prompt is only reachable by picking a pre-existing profile; ProfilePicker is select-only with no create/edit/preview and no surfacing of the injected AGENTS.md/rules. Users can't author instructions for a one-off run without leaving the composer.

### Unify slash discoverability — skills/custom commands in the launcher, not just templates
In the launcher '/' matches only prompt templates; skills and project/custom commands exist only mid-conversation, so the same keystroke surfaces different capabilities depending on whether a conversation exists.

### Sidebar sort options, pinning, and per-conversation tags
Within-group sort is hard-coded to updatedAt desc with no user control, no pin/favorite, and no per-conversation tags (only project-group rename) — thin for organizing many runs.

### Export JSON + copy-transcript-to-clipboard alongside Markdown
Export is Markdown-file-only; no JSON (tooling/replay) and no clipboard copy. The More menu has room and both are common in agent UIs.

### Diff viewer options (word-wrap, unified/split, copy diff/file, expand context)
The diff shells have no wrap/split/copy/expand-context controls and force-wrap long lines inconsistently — feature-thin vs Cursor/Zed/Claude Code.

### Per-run cost/token budget cap; ComposerMode as a per-run (not global-mutating) choice
Cost is read-only with no cap to stop a runaway autonomous run; and ComposerModePicker silently rewrites the global default for all future conversations — a surprising side-effect that should be an explicit 'Set as default' affordance.

## Completeness critic — gaps & reprioritization

### Gaps
- RUNTIME PERFORMANCE / STREAMING-SCROLL is entirely absent from the plan. MessageList (src/components/agents/chat/MessageList.tsx) maps every message with no virtualization — a long agent transcript renders hundreds of tool cards, each a Prism-highlighted MarkdownRenderer. Worse, useScrollState (src/components/agents/hooks/useScrollState.ts:42-50) fires messagesEndRef.scrollIntoView({behavior:'smooth'}) on every change to the `messages` array, i.e. on every streaming token delta. This is a felt 'feels 2nd-rate' jank that no amount of token-snapping or entrance-animation (the only thing the 'motion' theme covers) will fix. The plan's motion/perf theme covers entrance animation but ignores hot-path runtime perf.
- ROBUSTNESS: no ErrorBoundary anywhere in the Agents tab. The primitive exists (src/components/ui/ErrorBoundary.tsx) and the inventory notes it, but grep shows zero usage in src/components/agents/ or AgentsView.tsx. A single throwing tool card, malformed diff, or markdown crash blanks the entire tab. The plan rebuilds the card and diff systems (high-churn, crash-prone work) without ever proposing to wrap the panes in a boundary — a cheap, high-value safety net that should accompany that refactor.
- NOTIFICATIONS are wired wrong on the main Agents path and the plan never touches them. apiAgentListeners.ts:264/329 calls only notifyConversationDone (src/lib/notifications.ts:124), a parallel function that bypasses the user's notification prefs entirely — it checks only Notification.permission, ignoring useNotificationStore.enabled / onlyWhenUnfocused / onSessionComplete / the 5s debounce that notifySessionComplete honors. Meanwhile the richer, pref-gated notifyApprovalNeeded() exists but is wired ONLY to the orchestrator/flight path — so the api-agent (the actual Agents tab) fires NO desktop notification when it pauses for a permission approval, the single most important 'come back to me' moment for a long-running autonomous run. This is both a correctness bug and a missing-option, and the plan's bug cluster omits it.
- A11Y is under-scoped for a CHAT surface. The structural a11y item correctly lists Modal focus-trap, Dropdown keyboard nav, composer combobox, and tablist/listbox semantics — but omits the central need of a streaming chat: an aria-live region announcing streamed assistant output, and polite/assertive announcements on status transitions (running→done/failed) and on approval-needed. grep shows aria-live exists only in AgentFilePane. Screen-reader users currently get silence during the entire agent turn. This should be elevated within the a11y item, not left implicit.
- The ONBOARDING overlay (AgentsOnboarding.tsx) is the literal first impression and is essentially un-reviewed — it appears once in the plan (a fade). It is always-mounted, full-screen, hand-rolled instead of the shared Modal, its cards use raw accent bg tints (bg-accent-blue/10 etc.) rather than the contract recipes, and dismiss is click-anywhere with no escape/keyboard path. For a goal framed as 'modern first impression vs Workspaces,' the welcome surface deserves an explicit token/Modal-consolidation pass.
- LAYOUT FLEXIBILITY is under-covered: the only structural layout item is header-height alignment. But the inspector is drag-resizable + persisted (AgentInspectorPane.tsx:43-130) while the sidebar is hard-fixed w-[240px] (AgentSidebar.tsx:325) and not collapsible, and the chat can't be widened by collapsing either rail. There are also zero responsive breakpoints (no md:/lg:) across AgentsView, so on a narrow window all three fixed panes get crushed. The 'feels constrained' tell from inconsistent/missing resize+collapse is bigger than the ragged top-edge the plan focuses on.
- REGRESSION-TEST risk is unaddressed. The plan fixes ~30 bugs and splits a 1839-line god store, but never proposes regression tests despite existing __tests__ dirs (AgentInspectorPane.test, AgentInputArea.attachments.test). The createApiConversation options-object refactor and the failTurn/patchConversation extraction in particular are silent-correctness-shift risks (the 18-arg signature) that demand test coverage as part of the change, not after.

### Reprioritize
- Insert a NEW top-priority directly after the data-loss item (#1) and ABOVE the cosmetic token pass: 'Fix the notification path + wrap panes in ErrorBoundary.' Approval-needed/done notifications and crash isolation are correctness+retention with tiny lift; they currently rank nowhere, yet they outweigh the card-system/diff-rebuild work (current topPriorities #9) for a long-running autonomous-agent product.
- Elevate streaming/runtime performance into topPriorities (it is currently absent). Virtualize MessageList and debounce/instant-scroll during streaming (drop behavior:'smooth' per-token) belongs alongside or just below the correctness-bug item — it is an independent, felt 2nd-rate cause that the cosmetic and motion passes do not address.
- Within the 'build the missing primitives' priority, pull Toast forward and bind it to the notification fix: error feedback (alert()/console.warn), approval-needed, and turn-complete all share the same missing non-blocking-feedback surface, so building Toast unlocks three findings at once and should not wait behind Tooltip/Badge.
- The card-system unification and full diff-viewer rebuild (current topPriorities #9) are the largest-lift items and the least tied to the stated goal/correctness; move them DOWN relative to the notification/ErrorBoundary/perf/a11y items. They are 'nice modern' but not what makes the tab feel 2nd-rate the moment you open it.
- Within the a11y structural item, reorder so aria-live for streaming output + status/approval announcements is named first (it is the chat's primary a11y need), ahead of tablist/listbox semantics.
