Chapter 01

Getting Started

A fast, opinionated tour of PacketADE — what it is, how to install it, and what you'll see the first time you launch it.

What is PacketADE?

PacketADE is a Tauri v2 desktop IDE that unifies every AI coding agent you use into a single multi-pane cockpit. It wraps the major CLI agents — Claude Code, OpenAI Codex, Google Gemini, and OpenCode — alongside seven provider rows spanning Anthropic subscription/API, OpenAI subscription/API, MiniMax, OpenRouter, and local Ollama so you can run them side-by-side, share context between them, and stop paying for the same work twice.

If you've spent a week bouncing between three terminal tabs, a kanban board, a browser full of dashboards, and a notes app tracking which agent knows what, PacketADE is the fix. Flight Deck orchestrates multi-step work across agents. Cross-provider cost tracking shows you exactly where your tokens went. BYOK means your keys stay local. Memory and Insights keep the useful context, so your next session doesn't start from scratch.

It's built for solo developers and small teams who want an AI-first IDE without committing to a single vendor's walled garden. You bring the keys; PacketADE brings the cockpit.

Key concepts

Workspace
A project folder PacketADE has opened. Sessions, flights, issues, and memory are scoped per workspace.
Session
A single running PTY pane — a shell, a CLI agent, or a terminal process tied to the workspace.
Flight
The top-level unit of work. A flight bundles issues, sessions, a plan, and status rollup under one name.
Agent profile
A saved configuration of provider, model, system prompt, tools, and defaults. Reusable across conversations.
API agent
A conversation driven directly through a provider's API with full tool use and streaming. No CLI required.
CLI agent
A conversation driven through a locally-installed vendor CLI (claude, codex, etc.) running in a PTY.
Memory
A persistent, searchable store of patterns, decisions, and events PacketADE has learned about your codebase.

Install & first run

Prerequisites

  • Node.js 18 or later
  • pnpm 8 or later
  • Rust toolchain (rustc and cargo) 1.70 or later
  • Tauri OS prerequisites: Windows — Visual Studio Build Tools with the C++ workload. macOS — Xcode Command Line Tools. Linux — libgtk-3-dev and webkit2gtk-4.1.

Option 1 — Download a release

Grab a signed installer for Windows, macOS, or Linux from the GitHub Releases page. Run it, open PacketADE, and skip ahead to the first-run section below.

Option 2 — Build from source

git clone https://github.com/packetloss404/PacketADE.git
cd PacketADE
pnpm install
pnpm tauri dev      # hot-reload dev mode
pnpm tauri build    # production build

The first pnpm tauri dev will compile the Rust backend, which takes a few minutes. Subsequent runs reuse the build cache.

Windows note: the Rust stable target's bin directory must be on PATH for Tauri dev builds. Add C:\Users\<you>\.rustup\toolchains\stable-x86_64-pc-windows-msvc\bin to your environment before running pnpm tauri dev.

First run

  1. PacketADE opens to the Welcome screen when no workspace is active.
  2. Click Open Project and pick a folder. PacketADE scans it and reports the CLIs it finds on your PATH.
  3. If a CLI is detected, you can start using it immediately — zero configuration.
  4. API agents need keys. Open Tools settings hub and add keys under API Keys. Chapter 2 covers this in detail.

Required CLIs & tools

Nothing is strictly required — PacketADE will run with no CLIs installed, using only API agents. But the more CLIs it finds, the more panes you can spin up.

On Windows, PacketADE resolves .cmd wrappers automatically (for example, claude.cmd is found when you reference claude) and prefers native .exe binaries when both exist. You shouldn't need to rename anything.

A five-minute tour

The fastest way to understand PacketADE is to use it. Follow these steps in order.

  1. Launch PacketADE and pick a project folder from the Welcome screen. The workspace opens with an empty pane.
  2. Press Ctrl+Shift+1 to open the Agents view. Click + New Agent. Pick a provider — try Ollama if you want free and local — choose a model, type "explain the architecture of this project", and press Enter. Watch the response stream in.
  3. Try a slash command. Type /help to open the cheatsheet; type /model to switch models mid-conversation without losing context.
  4. Mention a file. Type @ and start typing a path — the popover filters as you type. Press Tab to insert the reference. The agent receives the file contents inline.
  5. Open Flight Deck with Ctrl+Shift+6. Click + New Flight, give it a title, chat with Claude to draft milestones, then click Create & Launch. Your flight now coordinates issues and sessions under one roof.
  6. Open Cost Dashboard from the toolbar. Your first conversation is already there, broken down by provider, model, and token type.
Tip: That's the ten-thousand-foot view. Chapter 2 is a full deep dive on the Agents view — profiles, slash commands, file mentions, tool-use approvals, and how to mix CLI and API agents in the same conversation thread.
Chapter 02

Agents & Chat

PacketADE runs two kinds of AI agents side by side: the familiar terminal-based CLIs you already know, and a first-class API-backed agent with streaming, tool use, and inline diffs. This chapter covers both — when to pick each, how to wire up keys, and every surface of the Agents view from slash commands to the voice mic.

CLI vs API agents

PacketADE treats agents as a duality. A CLI agent is a real terminal session: PacketADE spawns the upstream binary (claude, codex, gemini, or opencode) inside a PTY and renders its output verbatim. You get the exact UI the vendor ships, warts and all. An API agent is a Rust-side agentic loop driven by the provider's raw inference API — PacketADE owns the system prompt, the tool schema, the streaming, and the UI.

Both modes live in the same Agents view. You decide per conversation which one you want.

FeatureCLI (PTY)API
SetupInstall the vendor CLI on PATHPaste an API key (or run Ollama locally)
Tool useWhatever the CLI implements5 built-in tools, runtime-enforced
StreamingRaw terminal bytesToken-level chunks via Tauri events
PersistenceEphemeral — exits with the PTYJSON files under ~/.packetade/conversations/
PermissionsVendor-controlled bypass flagsYou own the sandbox; tools run in project root
Cost trackingBest-effort from vendor outputExact token + dollar cost per turn
Use whenYou want the real agent UI unchangedYou want diffs, audit, and reproducibility
Rule of thumb: API mode gives you tool use plus reviewable diffs. CLI mode gives you the real agent UI. Pick API when you want to trust-but-verify; pick CLI when you want the vendor experience as-shipped.

The Agents view

The Agents view is a three-column surface. On the left is the AgentSidebar, a 240-pixel rail listing every conversation you've ever started. The center/right is either the AgentInputArea (when no conversation is selected, a blank-slate composer for starting something new) or the AgentChatPane (when one is selected, the full conversation transcript).

AgentSidebar

  • Conversations are grouped by project folder so workspaces stay separated.
  • Each row shows a status dot, agent label, message preview, and relative timestamp.
  • A trash icon appears on hover and removes the conversation file from disk.
  • The active conversation is highlighted; click to switch, or hit Ctrl+N for a fresh one.

AgentInputArea

The blank-slate composer surfaces every knob you need to start a new conversation:

  • Provider dropdown — pick between CLI agents and the seven provider rows.
  • Model dropdown — filtered to whatever the selected provider supports.
  • Profile dropdown — defaults to Auto (Optimized).
  • Mic button — one-tap voice capture (see Voice input).
  • Project/repo selector — sets the working directory for the agent.
  • Textarea — placeholder reads "What would you like to work on?".

Beneath the textarea, a help strip reminds you: Enter to send · Shift+Enter for newline · Ctrl+N for new agent · @ to mention a file.

AgentChatPane

Once a conversation is active, the pane swaps in. The header carries a status dot, the agent label, the project folder, message count, an inline model switcher, and a close button. User messages are right-aligned in blue. Assistant messages are left-aligned and may contain plain text, tool-call cards, and a cost pill. When the agent is idle, three Quick Action buttons appear: Continue, Explain, and Undo. The composer at the bottom reads "Send a message..." and the send button is green when idle, red (as a Stop control) while streaming.

Start your first conversation
  1. Open the Agents view from the toolbar.
  2. Pick a provider. For a zero-setup path, choose Ollama.
  3. Pick a model, profile, and project folder.
  4. Type your request and press Enter.
  5. Watch the transcript stream in; use Esc or the red Stop button to cancel.

API keys & BYOK

Every BYOK provider needs one key, stored once. Keys live in your operating system's native keyring — Keychain on macOS, Credential Manager on Windows, Secret Service on Linux — under the namespace packetade:api-key-{provider}. They are never written to disk in plaintext and never exposed to the frontend JavaScript context.

  1. Open Tools → API Keys.
  2. Find the card for your provider (anthropic, openai, minimax, or openrouter).
  3. Paste the key into the input and click Save.
  4. Return to the Agents view; the provider is now selectable.

If you try to run an API agent without a key set, you'll see the error No API key configured for {provider}. Set one in Settings > API Keys.

Ollama: zero-key setup

Ollama runs entirely on your machine, so it needs no API key. Install it from ollama.com, then:

ollama serve
ollama pull llama3.3:70b

Once the daemon is listening on the default port, PacketADE will discover it automatically. Any model you've pulled will appear in the Ollama dropdown.

Keys on disk: keys live in the OS keyring, never as plaintext on the filesystem, and the frontend process never sees them — the Rust backend attaches them at request time.

Agent profiles

A profile is a named system-prompt override. PacketADE ships five, any of which can be selected from the profile dropdown in the input area. The choice rides along with each turn as system_prompt_override. Profiles persist in localStorage under packetade:profiles, and the active pick under packetade:active-profile.

IDNamePrompt
autoAuto (Optimized)empty — no override, uses workspace default
speed-runnerSpeed RunnerBe concise. Minimal explanation. Code-first. Skip confirmations. Output code immediately without lengthy preambles.
thorough-reviewerThorough ReviewerThink step-by-step. Explain reasoning. Consider edge cases. Review before executing. Be thorough in analysis.
security-auditorSecurity AuditorFocus on security vulnerabilities, injection risks, auth issues. Flag OWASP top 10. Review for XSS, CSRF, SQLi, and other common attack vectors.
refactor-proRefactor ProFocus on clean code, DRY, SOLID principles. Suggest refactoring opportunities. Improve readability and maintainability.
Create a custom profile
  1. Open the profile dropdown and choose New profile….
  2. Give it a name, a pill color, and write a system prompt.
  3. Save. The profile appears at the bottom of the list and is immediately selectable.
  4. Switching profiles mid-conversation affects only subsequent turns; past messages are not rewritten.

Conversational features

A conversation is a stream of turns. You type, the agent streams back. If the agent is an API agent, it may interleave tool calls: each call shows up as a collapsible card in the transcript, followed by its result. At the end of a turn, a cost pill (for example 245 tok · $0.0034) is rendered beneath the assistant message when pricing data is available for that model.

Every conversation exposes a lifecycle status that governs what the UI lets you do:

active
The agent is streaming. The send button is red and acts as Stop. Anything you type and submit is queued; it will send automatically when the turn ends, tagged with a (queued) badge.
idle
Turn complete, awaiting your next message. Quick Action buttons (Continue, Explain, Undo) appear. Queued messages drain here.
done
Conversation finished cleanly. You can still send a follow-up, which flips it back to active.
failed
The last turn errored — typically a missing key, network failure, or provider refusal. The error message stays in the transcript so you can retry.

Under the hood, the API agent loop emits events scoped by session ID: api-agent:chunk:{id}, api-agent:tool-start:{id}, api-agent:tool-result:{id}, api-agent:done:{id}, and api-agent:error:{id}. The chat pane subscribes to these to render in real time.

Slash commands

Type / at the start of the composer (or immediately after whitespace) to open the slash popover. Four commands are available:

CommandAction
/clearClear the message list, keeping model, project, and profile.
/modelOpen the model dropdown in the chat header.
/helpInsert a system message with the full keybinding cheatsheet.
/newStart a fresh conversation with the same agent, model, and profile.

Navigate with ↑↓, accept with Tab or Enter, dismiss with Esc.

File mentions (@)

Typing @ opens the file mention popover. It fuzzy-matches against the project's file tree and returns up to 20 results, debounced at 100 ms so fast typing stays smooth. Under the hood this calls list_project_files with your filter string.

  1. Place your cursor where you want the reference to land.
  2. Type @ followed by any part of the path — @authctrl happily finds src/auth/controller.ts.
  3. Arrow to the result, press Enter or Tab.
  4. The path is inserted as @src/auth/controller.ts with a trailing space, ready for the next word.

API agents treat mentioned paths as strong hints: they will typically call read_file on them before answering.

Tool diff view

Whenever an API agent invokes the write_file tool, the corresponding tool card renders as an inline diff rather than a collapsed JSON blob. The header shows +N / −M line stats, and the body shows a line-by-line diff computed with diffLines. The original file is fetched via read_file_for_diff so the comparison is against what's on disk at diff time, not at agent-request time.

The component renders in three states:

  • Loading diff… — the original is still being read.
  • New file badge + full content — the agent is creating a file that didn't exist.
  • Side-by-side diff — the usual case: additions in green, removals in red.
Tip: inline diffs make autonomous edits auditable. You scroll the transcript and see every write the agent made, in context, without opening a separate review pane.

Voice input

The mic button in the input area starts voice capture. If you have a native Whisper model downloaded, PacketADE uses it — it calls listWhisperModels() on startup, and the presence of any installed model flips the hook into native mode. Otherwise it falls back to the browser's Web Speech API. Recognition is locked to en-US.

The mic is gray when idle and turns a pulsing green while listening. When you stop, the transcript is appended to whatever is already in the composer — it never overwrites — so you can dictate in bursts, edit by keyboard, then dictate again. Note that if you pause mid-sentence with repeated numbers or digits, Whisper's built-in dedupe may collapse them; the Web Speech fallback does not.

Tool runtime

API agents get exactly five tools. They are implemented in Rust and enforced at the runtime boundary — the agent cannot access anything else, no matter what the prompt asks for.

ToolParametersLimits & notes
read_file{ path }Returns file text. Max 2 MB.
write_file{ path, content }Creates or overwrites. Auto-creates parent directories. Triggers the inline diff view.
list_directory{ path }Returns entries; directories are prefixed with [DIR].
bash{ command, timeout? }Runs in the project root. Output capped at 256 KB. Default 30 s, max 120 s. Returns { stdout, stderr }.
grep{ pattern, path?, include? }Returns file:line:content rows.
25-iteration ceiling: the agentic loop is hard-limited to 25 tool calls per turn. When the cap is hit, the loop exits cleanly with a summary message rather than looping forever. If you see a turn terminate at the limit, split the task or raise it to a thorough-reviewer profile and let the agent plan more deliberately.

Conversation persistence

API conversations are saved to ~/.packetade/conversations/{id}.json, debounced at 500 ms so streaming doesn't hammer the disk. On startup, the frontend calls load_conversations and populates the sidebar. Everything you see in the sidebar corresponds to a file on disk, one-to-one.

  • Export — copy the relevant .json file out of ~/.packetade/conversations/. It's a plain, human-readable record.
  • Backup — sync the whole directory to your dotfiles repo or a cloud drive.
  • Delete — the trash icon on each sidebar row removes the file from disk and the row from the list. There is no soft-delete.
PTY sessions do not persist. Only API conversations are written to disk. When you close a CLI agent session, its scrollback is gone — that's a property of the underlying vendor CLI, not a PacketADE choice. If you need a record, switch to the matching API provider.
Chapter 03

Workspaces, Flights & Planning

PacketADE organizes work in three tiers: workspaces bundle the panes, agents, and terminals you use day to day; flights capture the missions those agents run against; and the planning surfaces — issues, insights, ideation, and memory — keep the whole thing honest. This chapter walks through each layer, from splitting your first pane to retiring a flight.

Workspaces & panes

A workspace is a named project context that bundles multiple AI agents and terminal panes scoped to a single project directory. It is deliberately more than a generic "project" — where a project is just a path, a workspace remembers which agents run in which panes, which models they use, which system prompts are injected, and whether bypass-permission toggles are on. Open a workspace and your entire rig comes back exactly as you left it.

Creating and switching

There are three ways to create a workspace:

  • From the Welcome screen, click New Workspace.
  • From the Toolbar, use the workspace tab and choose New.
  • Press Ctrl+Shift+W from anywhere in the app.

Switch between workspaces using the dropdown at the top of the Workspace view. Each entry shows the name and project path, and switching is near-instant — state is restored from local persistence.

The tiling layout

Workspaces use a tiling pane system. Split the focused pane with Ctrl+\, focus panes by index with Ctrl+1 through Ctrl+4, and drag the divider between any two panes to resize. The toolbar also exposes preset layouts for quick reflow:

1x1 1x2 2x1 2x2 2x3 3x2

Close a pane with its X. If only one pane remains, the close affordance is hidden — there must always be at least one pane in a workspace. Per-pane state that gets persisted includes the session ID, model override, system prompt, the bypass-permission toggle, and an optional keep terminals alive flag so PTYs survive when you switch away to Issues or Insights and back.

Tip: Enable keep terminals alive for long-running agents. Without it, PTYs are torn down when the workspace view unmounts.

PTY sessions

Every terminal inside a pane is a real pseudo-terminal (backed by portable-pty) running one of the following:

claude codex gemini opencode bash zsh powershell cmd ssh

Starting a session

  1. Click a pane's CLI icon to open the session picker, or
  2. Run Quick Claude Session (or the Codex/Gemini equivalent) from the command palette, or
  3. Add an agent to the workspace — a session is launched for that pane automatically.

The launch dialog exposes the CLI choice, an agent profile, a model override, extra CLI flags, and environment variables. For Claude, the bypass-permission toggle lives here. Recent history includes a fix that stopped PacketADE from passing Claude's bypass flag to OpenCode by accident — if you use both CLIs, you benefit from that transparently.

Working in the terminal

Terminals are powered by xterm.js with roughly 1000 lines of scrollback. Mouse selection auto-copies to the clipboard; paste with Ctrl+Shift+V. Resizing the pane sends SIGWINCH to the child — run stty size to confirm the new dimensions were received.

Lifecycle

A session moves through three states: start → running → stopped. The pane's kill button sends SIGTERM first and escalates to SIGKILL if the child does not exit. For a graceful interrupt, press Ctrl+C inside the terminal.

Windows: PacketADE auto-resolves .cmd wrappers (for example, claude.cmd, codex.cmd) and prefers .exe binaries. You do not need to configure anything explicitly.

Status bars & git info

Each pane has a local status bar; the global status bar sits at the bottom of the window. They share a polling cadence: the useStatusLine hook ticks every 5 seconds, and useGitInfo refreshes every 10 seconds. If a status bar has not received an update in 30 seconds, it dims to 50% opacity so you know the data is stale.

Claude pane status bar

Shows the model name in blue, the context usage percentage (< 60 60-80 >= 80), accumulated cost in dollars, the current git branch, and the session duration. Hover the context pill for a breakdown of input, output, and cached tokens.

Codex pane status bar

Shows model, context percent, rate-limit headroom, reasoning-effort setting, and CLI version. Hover for detailed token usage.

Global status bar

Counts panes by type (Claude, Codex, shell, etc.), shows total active sessions, and rotates through keyboard-shortcut hints.

Session history

Reach Session History from the Toolbar History button or with Ctrl+Shift+4. Two tabs sit at the top:

Prompt History
Every prompt you have sent across every session, newest first.
Active Sessions
The panes currently running, with uptime and token counters.

A search bar at the top filters by message content; a project dropdown narrows to a specific folder. The Refresh button re-reads history from disk, which is useful after another tool has written to the transcripts.

Flight Deck

A flight is PacketADE's top-level planning unit — a mission composed of milestones, tasks, and linked issues. Flights roll their status up automatically from their contents, so the board tells you what needs attention without manual grooming.

Layout

Flight Deck is a two-panel view. The left rail groups flights by status:

Attention Active Review Draft Done Cancelled

The right panel shows the selected flight: milestones, the execution tile, approvals, a chronological timeline, a coordination feed from participating agents, and a deploy section if the flight has a release tied to it.

Status rollup order

The rollup is evaluated in three tiers. Tasks are evaluated first — if any task is approval_needed the flight lands in Attention; if any task is failed the flight is failed; if all are done the flight moves to review; any running or queued task keeps it active; blocked also surfaces as active. If there are no tasks, linked issues decide: blocked or needs_human pause the flight; all done marks it done; any in_progress or qa keeps it active. Finally, if nothing upstream applies, the manual status you set is respected.

Blockers and collisions

Tasks in approval_needed always bubble into the Attention group. Issues in blocked or needs_human pause whichever flight they are linked to. PacketADE also runs file-collision detection: two tasks cannot simultaneously claim the same files, preventing agents from stomping each other.

Creating & editing flights

Click + New Flight in Flight Deck, the Flights view, or the main toolbar. The modal opens with two panels side-by-side: an AI chat on the left for drafting the plan, a form on the right for the data you will actually save.

The chat panel

The chat streams Claude responses via flight-chat:chunk and flight-chat:done events (separate channels from Insights to avoid collision). Claude may embed JSON codeblocks that unlock one-click actions:

json:flight
A suggestion for title, objective, and priority. An Apply Suggestion button copies the fields into the form.
json:flight-plan
A full plan including milestones and tasks. An Apply Plan button populates the preview tree.

The form panel

  • Title (required).
  • Objective — multiline, supports markdown.
  • Priority buttons: Low, Medium, High, Critical.
  • Flight plan preview — a tree of milestones and tasks, editable inline.

The footer offers Create Flight or Create & Launch. Submit the form with Ctrl+Enter.

Status lifecycle

draft
You are still thinking. Not visible in Active.
planning
Milestones and tasks being assembled, often via the AI plan.
ready
Launchable, waiting on a go signal.
active
Work is in flight; tasks or issues are moving.

Temporarily halted; toggles with active.

Picking a priority

  • Low Background polish, non-urgent cleanup.
  • Medium The default — normal feature work.
  • High Time-sensitive; surfaces above default in sorts.
  • Critical Incident, outage, or release blocker.

Editing and deleting

Click a flight in the left list to open its detail. Titles are edited inline; milestones and tasks are edited in place. Changes auto-save through syncFlightsToBackend. To delete, hover the flight in the sidebar and click the X. There is no confirmation dialog — this is destructive.

No undo. Delete is immediate and unconfirmed. If you want to keep a record, move the flight to cancelled instead.

Linking issues

From either the New Issue form or the Issue Detail view, pick a flight from the dropdown. PacketADE calls flightStore.addIssueToFlight and issueStore.assignToFlight together so both sides of the link stay in sync. Unlink via the remove button on the flight card. One caveat: deleting an issue does not auto-unlink it from its flight — you need to clean that up manually.

Kanban issues

Open the issue board from Toolbar → Issues or with Ctrl+Shift+3. Columns, left to right:

To Do In Progress QA Done Blocked Needs Human

The Done column is hidden unless you toggle Show completed.

Creating an issue

  • Labels — multi-select; defaults include bug, feature, enhancement, refactor, docs, api, frontend, working, devops.
  • Epic dropdown.
  • Acceptance Criteria — add as many checkboxes as you need.

Insights chat

Open Insights from the Toolbar (lightbulb icon). The view has a sessions list on the left with a + New Conversation button and the chat transcript on the right. Ask natural-language questions about the codebase; Claude streams answers with full project context, using the standard event channels insights:chunk, insights:done, and insights:error.

The brain icon in the header toggles Memory active / Memory off. When active, learned patterns are injected as extra context at the top of each prompt. Under each assistant message a Send to terminal button forwards suggested commands to your currently focused session, so you can go from question to execution without copy-pasting.

Ideation scanner

The Ideation Scanner lives in the sidebar under its own lightbulb icon — distinct from Insights, despite the visual similarity. Use it to surface improvement suggestions proactively.

  1. Pick the workspace to scan.
  2. Choose idea types: Code Improvements, Security, Performance, Code Quality, Documentation, UI/UX. All six are enabled by default.
  3. Click Scan Now. Claude streams ideas in grouped batches.

Each idea shows a title, a severity pill (Low Medium High Critical), the affected files, and a suggestion. Ideas carry a status of Active, Promoted, or Dismissed.

Actions per idea

  • Promote — pins the idea to the top of its group.
  • Dismiss — hides it unless Show dismissed is on.
  • View Details — expands the full suggestion.
  • Convert to Issue — creates a new issue with the title, description, priority, labels, and acceptance criteria pre-filled.

Groups can be collapsed and expanded. A header count summarises state like 42 ideas (31 active, 7 converted, 4 dismissed). Ideas are stored per-workspace, so switching workspaces yields a different backlog.

Chapter 04

Integrations, Tools & Settings

PacketADE is most useful when it is wired into the rest of your toolchain: GitHub for tickets and PRs, a deploy pipeline that runs from the app, MCP servers that extend every agent's toolbelt, quality analysis on demand, and a single Tools hub that exposes every knob. This chapter is the reference for each of those surfaces, plus the Cost Dashboard and the module system that keeps the sidebar extensible.

GitHub integration

The GitHub view is reachable from the sidebar or the toolbar. On first launch you will see an empty auth screen — paste a Personal Access Token with repo scope and hit Connect. The token is handed to the Rust backend and kept in the OS credential store (Windows Credential Manager, macOS Keychain), but it is not persisted across app restarts — you reconnect on every launch. Treat it like a session cookie.

Generating a token

  1. Go to GitHub → Settings → Developer settings → Personal access tokens.
  2. Click Generate new token (classic or fine-grained both work).
  3. Give it repo scope.
  4. Copy the token and paste it into PacketADE. It will not be shown to you again.

Browsing issues and PRs

Once connected, select a repo from the dropdown. Two tabs sit at the top: Issues and Pull Requests. A search box filters the visible list by title or number. Clicking an item opens the detail pane on the right with labels rendered as color-coded pills, the full markdown body, author, open date, and an Open in GitHub external link.

Triaging into the board

The green Import to Board button creates a kanban card using the template [GH-{number}] {title}, copies the body into the card description, preserves labels, and sets status todo with priority medium. From there the card behaves like any other PacketADE issue and can be linked to flights or launched into a session.

Opening pull requests

The purple New PR button opens a modal with fields for title, description (markdown), head branch (required), and base branch (defaults to main). On success the new PR URL is returned and surfaced inline; click it to jump into GitHub.

Investigate with AI

The blue Investigate with AI button on any issue spawns Claude against the current project. It takes 10–30 seconds and renders the result as markdown in an AI Investigation panel. Use it to ask "which files are likely to change" or "what is the minimal repro" before committing engineering time.

Heads up: the PAT is intentionally not persisted. REST calls share a 5000 req/h rate limit, so if you script bulk imports keep an eye on headers. The Review Queue view is a separate surface that collects pending approvals generated by flights — click an entry to triage.

Deploy pipeline

The Deploy view is a core view, not a module. Reach it via the rocket icon in the toolbar. You can either create a deploy config manually or let PacketADE auto-detect one from project files.

Auto-detection sources

On first open, Deploy scans the project in this priority order:

  1. packetade.deploy.json at the project root (explicit wins).
  2. package.json scripts: build, deploy, start.
  3. Framework hints: vercel.json, netlify.toml, Dockerfile.

Running a deploy

The Add Config modal asks for a name, a command (e.g. npm run build && npx vercel --prod), and a working directory that defaults to the project root. Select the config on the left pane and click the green Play icon. Validation runs first; then live terminal output streams on the right.

Status moves through a spinning loader and resolves to a check on exit 0 or a red X on any non-zero code. The Run History list at the bottom records timestamp and duration for each run — click a row to expand the captured output inline.

Known gaps: no environment-variable UI yet (use a .env file loaded by your tool of choice), no cancel button once a run starts, and every command runs from the project root. Windows shell quirks like npm vs npm.cmd are handled for you.

MCP Hub

The Model Context Protocol is an open spec for tool and resource exposure: an MCP server publishes callable tools (e.g. "read_file", "query_db"), and a client like Claude or Codex discovers and invokes them. A common example is @modelcontextprotocol/server-filesystem, which adds sandboxed disk access to any client that connects. PacketADE exposes two cards in the Tools hub to manage this: MCP Servers and MCP Provider.

Adding a server

The Add server modal takes:

Name
Identifier used by clients. Must be unique within its scope.
Command
The executable — typically npx, python, node, or an absolute path.
Arguments
Space-separated arguments passed to the command.
Environment variables
KEY=VALUE pairs; one per line.
Scope
Global for cross-project use, or Project for this project only.

Global servers land in ~/.claude/settings.json; project servers land in ./.mcp.json at the project root. The pencil icon reopens the modal for edits (the name is locked once created); disabled servers show a badge in the list; the trash icon deletes with a confirmation dialog.

MCP Provider card

The Provider card is a readiness/configuration surface for exposing PacketADE-owned resources through MCP. Today it persists the enabled state, port, scope, resource catalog, and per-tool allow list in the frontend store; the external MCP listener is not wired yet, so toggling it does not make PacketADE reachable from other clients by itself. Tool routing — which agent or model handles which task type — is configured from Provider Routing in the Tools hub.

Collisions: two servers exposing the same tool name is undefined behavior — last-loaded wins. Namespace your tools if you run more than one server with overlapping features.

Code Quality

Open Code Quality from the Tools hub card or the Quality button in the toolbar. Pick a workspace from the dropdown (or accept the current one) and analysis runs in 10–30 seconds. Results appear in four tabs: Overview, Languages, Complexity, and Tests.

What the scores mean

Comment ratio
Percentage of lines that are comments. Ideal band is 15–30%. Very high ratios usually mean stale docblocks, not helpful commentary.
Test coverage
Percentage of files matching *.test.* or *.spec.*. Ideal is > 40%. This is file coverage, not line coverage — a rough proxy, not a replacement for a real coverage tool.
Cyclomatic complexity
Average branch count across functions. Ideal is < 5. Above 10 in any file is a refactor candidate.
Organization
Heuristic combining folder depth, file-size distribution, and module count.

The overall 0–100 score blends these with weights comment 20% / tests 30% / complexity 30% / organization 20%, then maps to a letter grade A–F. Overview also shows file count and a one-line language breakdown; the Languages tab drills down by language; Complexity lists hotspots sorted by score; Tests enumerates detected test files.

The green Get AI Insight button picks or creates a workspace and hands Claude 5–7 recommendations as a pre-loaded chat prompt — useful when the raw numbers don't point at an obvious fix.

Limitations: results are best for JavaScript, TypeScript, Python, Go, and Rust. Monorepos above 100k LOC can take 1–2 minutes to analyze. No historical trend tracking yet — each run is a snapshot.

Crash Viewer

Open the Crash Viewer from the Tools hub Crash Reports card. It reads reports out of ~/.packetade/crashes/ (on Windows that resolves to %APPDATA%\packetade\crashes\). Each entry shows a timestamp and a one-line summary; the eye icon opens the full stack trace in a modal; the trash icon deletes a single report.

Reports persist indefinitely — there is no automatic cleanup, so prune them by hand when the list gets long. If you hit a reproducible bug, open the stack trace, copy it, and paste it into a GitHub issue against the PacketADE repo.

Bug reports: stack traces make good attachments. Grab one from the Crash Viewer, redact paths if needed, and attach it when filing issues.

Dictation & voice-to-text

The full Dictation view is reachable from the VT purple button in the toolbar, the Dictation card in Tools, or the Ctrl+Shift+D shortcut. The center of the view is a large microphone button ringed in green — click it to start, and it pulses red while recording. A 32-bar live waveform visualizes audio level, and a REC chip appears in the bottom status strip whenever capture is live so you can tell the mic is hot from anywhere in the app.

Stop by clicking again, pressing the bound shortcut, or Escape to cancel. Audio is handed to a local Whisper model for transcription; the status strip flips to Transcribing… while processing. Completed transcripts auto-append to history and are searchable by keyword.

Keyboard shortcuts

ShortcutAction
Ctrl+Shift+V (hold)Push-to-talk — records while held, transcribes on release.

All four are registered as OS-level global shortcuts via tauri-plugin-global-shortcut, so push-to-talk works even when PacketADE is not the focused application. In-window listeners are kept as a fallback for cases where OS registration is denied (e.g., macOS Accessibility permission not granted).

Focus-aware insertion

PacketADE tracks the most recently focused text input across every view. When transcription finishes and the Auto-paste after transcription setting is on (default), the result is inserted at that input's cursor — whether it's an agent chat box, a flight title, an issue description, the prompt library, or anywhere else you've typed recently. Terminal panes and the Dictation view's own search box are deliberately excluded.

If you dictated from another app via the global hotkey and no PacketADE input was tracked, the transcript falls back to the system clipboard so you can paste it wherever you actually need it.

Analytics

The dashboard surfaces Total Words, Avg WPM, Fastest WPM, Avg Sentiment, Total Time, Entries, Daily Streak, an estimated Time Saved, and a Vocab Diversity score. Charts include Sentiment over Time (bar), WPM over Time (line), Activity by Hour (histogram), Top Words (frequency bars), and Words per Entry (distribution).

Gotchas: native mode requires a Whisper model to be downloaded (checked via listWhisperModels()); the Web Speech API is a fallback but less accurate. Sentiment is a heuristic over word polarity, not an ML emotion classifier. Escape only stops capture client-side — the backend has no abort command yet, so the captured audio still runs through transcription once before being discarded.

Cost Dashboard

Reach the Cost Dashboard from the Tools hub Cost card or the $ icon in the toolbar. It aggregates usage across every source PacketADE can observe: Claude CLI, Codex CLI, Claude subscription/API, OpenAI subscription/API, MiniMax, OpenRouter, and Ollama (local runs are almost always $0 but still counted for session totals).

Four summary cards sit at the top: Total Cost, Total Sessions, Input Tokens, and Output Tokens. When the Claude API is in use, two extra pills surface cache_read_input_tokens and cache_creation_input_tokens — a material discount once prompt caching kicks in. Below the cards, a daily chart renders the last 30 days as green bars; hover for per-day totals.

Module system

Modules are optional sidebar extensions declared as ModuleManifest objects in src/types/modules.ts. The registry lives in src/modules/registry.ts and currently ships three built-ins:

  • AI Ideation — codebase opportunity scanner.
  • Utility Scaffold — project templating.
  • AI Dictation — voice-to-text workspace.

Toggle modules on or off from the Tools hub Modules card. Disabled modules disappear from the sidebar immediately, and if you happen to be viewing one when you disable it the view closes itself. A manifest has these fields:

id
Stable identifier, used for persistence.
name
Display name in the sidebar.
description
Tooltip and Modules-card copy.
icon
A Lucide icon component.
iconColor
A theme token such as text-accent-blue.
component
The React view rendered when the module is active.
category
ai, utility, integration, or analysis.
enabledByDefault
Initial state on first run.
shortcutHint
Optional keybinding hint shown in the sidebar.

Adding a custom module

Create src/modules/my-module.ts, export a ModuleManifest, and register it in registry.ts by pushing it into moduleRegistry.

import { Zap } from "lucide-react";
import MyFeature from "./my-feature-view";

export const myModule: ModuleManifest = {
  id: "my-feature",
  name: "My Feature",
  description: "A custom module",
  icon: Zap,
  iconColor: "text-accent-blue",
  component: MyFeature,
  category: "utility",
  enabledByDefault: true,
};
No lazy loading: every registered module is imported at app startup, enabled or not. Keep module entry points light — lift heavy dependencies into the view component itself rather than the manifest file.
