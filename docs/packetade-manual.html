The Complete User Guide

PacketADE Manual

Everything you need to run every agent, orchestrate Missions, wire up integrations, and ship from one cockpit. Written to be readable top-to-bottom, or dipped into by chapter when you need the reference.

v0.9.3 Apache 2.0 Tauri v2 · React 19 · Rust · Node sidecar No telemetry · BYOK
Chapter 01

Quick Start

Install PacketADE, open a folder, and have a CLI agent talking to you in under five minutes. The rest of the manual is reference material; this chapter is the on-ramp.

What is PacketADE?

PacketADE is an open-source desktop IDE that unifies every AI coding agent — CLI and API — into a single multi-pane cockpit. It wraps the major CLI agents (Claude Code, OpenAI Codex, Google Gemini, OpenCode, and others from a 13-entry catalog) alongside eight API provider rows spanning Anthropic subscription/API, OpenAI subscription/API, OpenAI Agents SDK, MiniMax, OpenRouter, and local Ollama. You bring the keys; PacketADE brings the cockpit.

The product is built around four modes — pick the one that matches the shape of your task, then mix freely:

  • Flight Deck Spec a mission and let it run autonomously.
  • Workspace Tile CLI agents in worktrees and orchestrate them by hand.
  • Agents One focused, single-thread chat with tool diffs.
  • Issues AI-structured intake, then hand each ticket to a supervised agent.

Built for solo developers and small teams who want an AI-first IDE without committing to a single vendor's walled garden. Apache 2.0. No telemetry. Your keys, your models.

Naming note. This product was previously called PacketCode. It was renamed PacketADE to free that name for a separate TUI sibling. You may see lingering "packetcode" references in legacy data paths and localStorage migration code — that is by design.

Install & first run

Option 1 — Download a release

Grab the latest beta installer or package from the GitHub Releases page. Run it, open PacketADE, skip ahead to Your first workspace.

Beta distribution status: PacketADE is manual-install today. Windows Authenticode signing, macOS notarization, and the Tauri auto-updater are planned release-trust gates but are not enabled in the repo yet, so beta builds may trigger SmartScreen or Gatekeeper prompts.

Option 2 — Build from source

Prerequisites: Node.js 18+, pnpm 9+, Rust 1.70+, and the Tauri OS toolchain (VS Build Tools on Windows, Xcode CLT on macOS, libgtk-3-dev + webkit2gtk-4.1 on Linux).

git clone https://github.com/packetloss404/PacketADE.git
cd PacketADE
pnpm install
pnpm tauri dev      # hot-reload dev mode
pnpm tauri build    # production build

The first pnpm tauri dev compiles the Rust backend and the Node sidecar — expect a few minutes. Subsequent runs use the build cache.

Windows note: the Rust stable target's bin directory must be on PATH for Tauri dev builds. Add C:\Users\<you>\.rustup\toolchains\stable-x86_64-pc-windows-msvc\bin to your environment before running pnpm tauri dev.

Your first workspace

PacketADE opens to a Welcome screen when no workspace is active. From here:

  1. Click New Workspace.
  2. Pick a folder — either from the OS picker or from the Recents dropdown.
  3. Name the workspace. The folder path you picked is the project path.
  4. Click Save. The workspace opens with an empty mosaic pane.

That's it. PacketADE will scan for installed CLIs (Claude Code, Codex, etc.), auto-detect a GitHub remote if one exists, and remember every pane, model, and bypass-permission toggle for next time you open the workspace.

Your first session

Inside the workspace, the empty pane shows a launcher. The fastest path to your first agent:

  1. Press Ctrl+K to open the command palette.
  2. Type "claude" and pick New Claude session. A PTY pane spawns with the claude CLI live and ready.
  3. Alternatively, click the + New dropdown on the toolbar and pick New Claude session, New Codex session, New Mission, New Issue, or New deploy run.

If you'd rather chat with an API agent than drive a CLI, jump to the Agents view from the LeftRail and pick a provider. Ollama is the zero-key path — install Ollama, run ollama serve, and PacketADE will discover it on localhost:11434 automatically.

Five-minute tour: open a workspace, hit Ctrl+K, launch a Claude session, type "explain the architecture of this project", then try a Mission — click the Plane icon in the LeftRail and start a spec conversation. Read on for the deep dives.
Chapter 02

The Four Modes

Every PacketADE workflow falls into one of four modes — from fully autonomous Missions down to a single focused chat. Pick the mode for the work in front of you. They share memory, costs, and providers, so mixing them is free.

Mode overview

Mode 01 · Full Autonomous

Flight Deck

Write a spec. A Sonnet 4.6 planner decomposes it into milestones and tasks. Executors run end-to-end. You step in only on approval gates.

When: Large multi-step work you want to delegate.
Mode 02 · Semi-Autonomous

Workspace

Tile PTY-backed CLI agents in worktrees. Give each one a task, supervise mid-stream, reply, switch, branch, steer them in parallel.

When: Hands-on orchestration with bypass-perms within reach.
Mode 03 · Single-Thread Chat

Agents

One conversation, one API agent. Structured chat with tool diffs, slash commands, @-file mentions, and voice input.

When: Focused threads, exploratory Q&A, one chat is the right shape.
Mode 04 · AI-Structured Intake

Issues

Paste a spec. AI breaks it into discrete tickets. One-click Send to Workspace spawns a Claude pane in a worktree with the ticket as the opening turn.

When: You want AI to structure the work, you (or a supervised agent) drive the code.

Mode 1 · Flight Deck

Flight Deck is the most autonomous mode. You start a spec conversation with a planner agent (Claude Sonnet 4.6 by default) and describe the outcome you want. When you click Launch, the planner decomposes the spec into 2–4 milestones and 4–10 tasks, spawns one executor agent per task in its own git worktree, reacts to completions and failures, and only escalates when it genuinely needs your input.

Open it from the Plane icon in the LeftRail (Flight Deck), Ctrl+Shift+6, or the + New → New Mission entry in the toolbar dropdown. Chapter 6 covers the planner in depth.

See Missions on the roadmap

Mode 2 · Workspace

Workspace is where the keyboard meets the agent. You open a workspace at a project folder; inside, you tile multiple PTY panes — each one a real terminal running claude, codex, gemini, opencode, packetcode, or a plain shell. Panes survive view switches, models and bypass-permission toggles are remembered per-pane, and the mosaic layout (1×1 through 3×2) is one click away.

Open it from the Terminal icon in the LeftRail (Workspace), or Ctrl+Shift+W. Chapter 4 covers the workspace in depth.

Mode 3 · Agents

The Agents view runs structured single-thread conversations through one of eight API provider rows. Unlike a PTY session, an API agent is a Rust-side agentic loop that owns the system prompt, the tool schema, the streaming, and the UI. You get inline diffs on every write_file call, slash commands, @-mentions, voice input, and a cost pill on every turn.

Open it from the Sparkles icon in the LeftRail (Agents), or Ctrl+Shift+1. Chapter 5 covers API conversations in depth.

Mode 4 · Issues

Issues is more than a kanban board — it is the AI-structured intake layer. Paste a spec, PRD, design doc, or feature request into the Import Spec modal and a one-shot Claude OAuth session returns a list of inline-editable Issue drafts (title, body, acceptance criteria, labels, suggested epic). Accept the ones you want, and they land in the Backlog column grouped by a shared spec-import batch.

From any Issue card, click Send to Workspace to provision an Issue-bound git worktree, install a prepare-commit-msg hook that auto-appends Fixes #N trailers, and spawn a Claude pane in that worktree seeded with the issue body. When you commit, the trailer parser recognizes Fixes #N and flips the Issue to Done automatically. Open Issues from the LeftRail or Ctrl+Shift+3. Chapter 7 covers the close-loop end-to-end.

Chapter 04

Workspaces

A workspace is a named project context that bundles multiple AI agents and terminal panes scoped to one project directory. Open a workspace and your entire rig comes back exactly as you left it — which panes were open, which models they were using, which system prompts were injected, whether bypass-permission was toggled on.

Creating workspaces

Three entry points:

  • Welcome screen → New Workspace.
  • Toolbar workspace tabs → +.
  • Ctrl+Shift+W from anywhere.

The WorkspaceCreationModal exposes:

Name
Display name in the workspace tab strip.
Location
Local or Remote (SSH) — SSH lets you build against a fingerprint-verified server.
Folder
OS picker + a Recents dropdown. Browse is always available; if there are no recents the modal auto-jumps to the OS picker. Save is gated on a non-empty path so a workspace can never persist with projectPath: "". v0.8.8
Bypass permissions
Default for new panes. Defaults to off; can be overridden globally in Settings → Workspace.
GitHub auto-bind
If a git remote get-url origin exists, PacketADE stamps {owner, repo} onto the workspace. v0.8.0 Toggle off the global setting if you'd rather opt in case by case.

The workspace-aware folder picker

The folder icon in the toolbar changes its behavior based on what's active. v0.8.8

  • With an active workspace: the picker reads "Change folder for '{workspaceName}'" and writes through to that workspace's projectPath. The tooltip shows the path + workspace name.
  • With no active workspace: a follow-up modal asks whether to create a new workspace at the picked path or set it as the default for the next workspace.

Under the hood, layoutStore.projectPath is a synchronized mirror of the active workspace's projectPath. Remote workspaces (those with a serverId) skip the mirror so your last local path is preserved when you flip between local and remote.

Multi-pane mosaic

Workspaces use a React Mosaic tiling system. Each pane is a real PTY (xterm.js + portable-pty) running a CLI agent or shell. Split, focus, and resize:

  • Ctrl+\ — split the active pane.
  • Ctrl+1 … Ctrl+4 — focus panes 1–4 by mosaic leaf order.
  • Drag any divider to resize.
  • Preset layouts in the WorkspaceView toolbar: 1×1 1×2 2×1 2×2 2×3 3×2.

Per-pane state persisted across launches includes the session ID, model override, system prompt, bypass-permission toggle, and an optional keep terminals alive flag so PTYs survive view switches. WorkspaceView itself is always mounted under a display: none wrapper, so flipping to Issues and back never tears down a running agent.

Bypass permissions

The bypass-permission toggle lives at three levels:

  1. Per pane: a toggle in the pane header. Wins over all defaults.
  2. Per workspace: the default for new panes (set at workspace creation, editable in Settings).
  3. Global: Settings → Workspace → Default new workspaces to bypass permission prompts. The whole-app fallback.

The flag is passed through to the underlying CLI (e.g. Claude's --dangerously-skip-permissions). PacketADE was careful in v0.8.7 to stop passing Claude's bypass flag to OpenCode by accident — if you run both CLIs, you benefit transparently.

Remote (SSH) workspaces

Pick Remote (SSH) in the WorkspaceCreationModal to build against a server. You need a ServerConfig registered first (Settings → Servers) with a verified host fingerprint — PacketADE replaced TOFU host-key acceptance with explicit SHA256 pinning in v0.6.0. Once verified, enter a remote project path; a live probe reports DIR_GIT | DIR | FILE | MISSING within 8 seconds.

Remote workspaces are first-class for PTY sessions and most agent flows. A few features are explicitly gated:

  • Code Quality short-circuits with a "not yet supported on remote workspaces" message; the toolbar Quality button is disabled with a tooltip.
  • Editor pane shows a placeholder card; file tabs still render so open-files state is visible.
  • Flight Deck local-base targets filter out remote workspaces.
  • Sidecar providers (Anthropic OAuth + Codex OAuth) return a clear error rather than silently running locally when you point them at SSH.

SSH passwords live in the OS keyring under ssh-<ServerConfig.id>; the per-connection SshConfig always carries host_fingerprint from ServerConfig so host-key pinning is enforced.

Chapter 05

Sessions

PacketADE runs two kinds of AI sessions side by side: real terminal-based CLIs in PTY panes, and first-class API agents with streaming, tool use, and inline diffs. They share the Agents view UI, the cost dashboard, and memory — you pick the right one per task.

PTY CLI sessions

A PTY session is a real pseudo-terminal (backed by portable-pty) running one of the catalog CLIs. PacketADE auto-resolves .cmd wrappers on Windows (so claude.cmd works when you reference claude), and prefers native .exe binaries when both exist.

Launching

Three paths:

  • + New dropdown in the toolbar — pre-baked entries for New Claude / New Codex.
  • Click an empty mosaic pane → pick a CLI from the launcher dialog (CLI choice, profile, model, extra flags, env vars; bypass-permission toggle for Claude).
  • Command palette → "Quick Claude session" or equivalent.

Working in the terminal

Terminals are xterm.js with ~1000 lines of scrollback. Mouse selection auto-copies to the clipboard. Paste with Ctrl+Shift+V. Resizing the pane sends SIGWINCH to the child — run stty size to confirm.

The pane status bar (varies per CLI) shows model, context %, accumulated cost in USD, current git branch, and session duration. Hover for token breakdown (input / output / cached).

Lifecycle

A session moves through start → running → stopped. The kill button sends SIGTERM first, escalates to SIGKILL if needed. For a graceful interrupt, press Ctrl+C inside the terminal.

API agent conversations

The Agents view (LeftRail Sparkles, Ctrl+Shift+1) is a three-column surface. Left: AgentSidebar with every conversation you've ever started, grouped by project. Center/right: AgentInputArea for new chats, or AgentChatPane for an active one.

Last turn errored (missing key, network, refusal). The error stays in the transcript so you can retry.

Sidecar vs in-process

Two transports, one event contract. API-key providers run in-process in Rust via the LlmProvider trait (src-tauri/src/core/llm_provider.rs). The two OAuth subscription providers route through the Node sidecar (agent-sidecar/). Both emit identical api-agent:{kind}:{sessionId} Tauri events, so the chat pane never knows or cares which backend served a given turn.

Sidecar communication is newline-delimited JSON over stdio. The protocol version is currently 6 (see agent-sidecar/src/protocol.ts); the Rust supervisor reconciles versions on the ready event and warns — non-fatally — on mismatch. Entry-point resolution in priority order:

  1. PACKETADE_SIDECAR_PATH / PACKETADE_NODE_PATH env vars (for development overrides).
  2. Dev: CARGO_MANIFEST_DIR/../agent-sidecar/dist/index.js + system node.
  3. Release: resource_dir/agent-sidecar/dist/index.js + bundled Node via Tauri shell sidecar.

Slash commands, @-mentions, voice, and diffs

Slash commands

Type / at the start of the composer (or after whitespace) to open the slash popover. The base set:

CommandAction
/clearClear messages, keep model/profile/project.
/modelOpen the model dropdown in the chat header.
/helpInsert a keybinding cheatsheet message.
/newFresh conversation with the same agent/model/profile.
/usageInsert running token + cost totals.

Saved prompt templates from Settings → Advanced → Prompt Templates are exposed as kebab-cased slash commands. v0.8.6

@-mentions

Type @ to fuzzy-match the project's file tree (up to 20 results, debounced 100 ms). Arrow to a result, Tab or Enter to insert. The path lands as @src/auth/controller.ts with a trailing space. API agents typically call read_file on mentioned paths before answering.

Inline tool diffs

When an API agent invokes write_file, the tool card renders an inline diff — not a JSON blob. Header shows +N / −M stats; body shows the line-by-line diff (computed with diffLines against the on-disk file at diff time). New-file writes get a New file badge and the full content. Hover any added line and a + icon offers a Codex-style inline comment composer — queued comments fold into the next user turn as a File comments: preamble.

Voice input

The mic button in the composer starts capture. PacketADE prefers a local Whisper model if one is installed; otherwise it falls back to the browser Web Speech API. Transcripts are appended to whatever is in the composer — they never overwrite — so you can dictate in bursts, edit, then dictate again. Chapter 16 covers global push-to-talk and the analytics dashboard.

Tool runtime

API agents have five tools, enforced at the Rust runtime boundary. The agent cannot access anything outside this list, no matter what the prompt asks for.

ToolParametersLimits
read_file{ path }Max 2 MB.
write_file{ path, content }Creates or overwrites; auto-creates parents; triggers inline diff.
list_directory{ path }Directories prefixed with [DIR].
bash{ command, timeout? }Runs in project root. Output capped at 256 KB. Default 30 s, max 120 s.
grep{ pattern, path?, include? }Returns file:line:content rows.

The agentic loop is hard-limited to 25 tool calls per turn. At the cap, the loop exits cleanly with a summary — not infinite spin. If you hit the cap repeatedly, split the task or switch to a Thorough Reviewer profile.

Persistence

API conversations are saved as ~/.packetade/conversations/{id}.json (debounced 500 ms). The frontend hydrates the sidebar from this folder on startup. PTY sessions are not persisted — scrollback is gone when the pane closes. If you need a record, use the matching API provider instead.

Chapter 06

The Mission Planner v1

The Mission Planner is the autonomous core of Flight Deck. You write a spec; one Claude session owns the mission from there — decomposing into milestones and tasks, spawning executor agents per task, reacting to completions and failures, asking for approval when it needs to, and writing every move to a markdown journal you can read live. v0.7.0

Spec mode

From Flight Deck, click Start a mission. A spec-mode chat opens with a Sonnet 4.6 planner agent. Talk to it about what you want to build — goal, constraints, must-haves, nice-to-haves. The planner asks clarifying questions until it has enough to decompose; when you're ready, hit Launch.

Autonomous decomposition

On launch, the planner breaks your spec into 2–4 milestones, each containing 4–10 tasks. Each task is spawned as an executor agent (Claude Code in a dedicated git worktree) with the task brief, acceptance criteria, and a scoped tool surface. Tasks run in parallel where their file claims don't collide; collision-detection is part of the orchestrator.

The planner reacts to executor lifecycle events:

  • Task completed → review output, mark done, advance the milestone.
  • Task failed (retryable) → replan with a tightened brief. Rate-limit and network failures are exempted from the replan cap.
  • Task failed (terminal) → mark the milestone blocked, escalate via the approval gate.
  • Approval requested → surface in the toolbar Bell and the Review Queue; mission pauses until you respond.

Mission journal

Every planner action — tool call, decision, replan, escalation — is appended to an immutable markdown file at ~/.packetade/missions/<shortId>_<id>.md. The Journal tab on the mission detail pane renders it live. This is the audit trail; everything the planner did, in order, with timestamps. Open the file directly to grep across past missions.

Cost split & context compaction

The mission StatGrid splits costs into Planner spend (the controlling Claude session) and Executor spend (every spawned worktree agent). OAuth subscriptions also get a cumulative-token chip. The split makes it obvious when the planner is over-thinking and the executors aren't doing enough — or vice versa.

At 150K cumulative input tokens, the planner's conversation is summarized and the session is reset with the summary as priming context. Multi-day missions do not hit the context wall.

Approvals & safety rails

Approval is a first-class gate, not a CLI prompt. When the planner needs human input, it sends an approval_needed task into the Review Queue and pauses. The toolbar Bell turns red with a count; clicking it opens the queue, where you can approve / reject / amend inline. Wired in v0.8.7 so both permission-request and pending-edit events from API agents flip linked tasks to approval_needed.

Safety rails baked in:

  • Per-mode tool-call caps: 50 (planner) / 25 (executor) / 25 (helper).
  • Total task ceiling: 60 per mission.
  • Rate-limit detection with auto-resume after backoff.
  • Kill-switch button on every active mission.
  • Awake-stickiness watchdog — missions can't be left silently asleep.
  • Cold-start enforcement: active missions flip to paused on app restart so you confirm before resuming.

Deleting missions

Each Mission row has a hover-revealed trash icon. v0.8.7 Click once — the row enters a two-step confirm with a 3-second auto-revert. If the mission has running attempts or queued / approval tasks, the confirm copy escalates to "Active work — delete?". Confirmed deletion cascades to clear Issue.flightId back-references on every linked issue.

Chapter 07

Issues & Spec Import

In v0.8.5 the Issues pane was repositioned as a fourth user mode — AI-structured intake at the front, human-orchestrated CLI agents in Workspace panes at the back, with a commit-trailer auto-close loop in the middle.

Five-column board

Columns, left to right:

Backlog Up Next In Progress In Review Done

The Backlog column is the landing zone for spec-imported tickets. In Review auto-displays when an issue's linked Flight has a draft PR. Done is hidden by default; toggle Show completed to surface it. Legacy status enum values from earlier versions roll up — nothing falls off.

Spec import

The Import Spec button at the top of the board opens a two-stage modal: Paste → Review-and-accept. v0.8.5

  1. Paste a spec, PRD, design doc, or feature brief into stage 1. Submit.
  2. A one-shot Claude OAuth sidecar session (with an explicit anti-injection envelope on your input) returns Issue drafts.
  3. Stage 2 lists every draft — title, body, labels, acceptance criteria, suggested epic — all inline-editable and individually selectable.
  4. Accept what you want. The created Issues share a specImportBatchId so they're grouped semantically, and land in the Backlog column.

Send to Workspace

Every Issue card has a Send to Workspace CTA. Clicking it kicks off sendIssueToWorkspace:

  1. Provisions an Issue-bound git worktree (one branch per issue, sandboxed).
  2. Installs a prepare-commit-msg hook that idempotently appends Fixes #{n} and Run-By: PacketADE issue I-{id} trailers to every commit made inside.
  3. Spins up a workspace with one claude-code pane at the worktree path. The conversation is seeded with the issue title + body + acceptance criteria as the opening turn.
  4. Stamps workspaceId, sessionId, and sentToWorkspaceAt on the Issue. Status flips to in_progress and the view switches to Workspace.

Linked Issues show a → Workspace pill that jumps you back to the worktree pane. If worktree provisioning fails (uncommitted changes, branch conflict, non-git project), the workspace still opens in the bare project path — you just lose the auto-Done leg for that session.

Auto-Done on Fixes #N

The git_commit Tauri command parses commit-message trailers with a word-boundary-anchored regex. It recognizes Fixes / Closes / Resolves — case-insensitive, start-of-line only, optional colon. Rejects #42foo. Dedupes. Multiple trailers per message all parse.

On a match, it emits issue-watcher:fixed with the issueId, commitSha, and subject. The frontend listener auto-flips the matching Issue to done and appends a system audit comment: "Auto-closed by commit {sha7}: {commit_subject}".

CommitModal is Issue-aware: when the active workspace is bound to an Issue, the message textarea opens with Fixes #{n}\n\n pre-seeded and a "🔗 Linked to Issue #N: {title}" hint above. One-shot per open — it never overwrites your typing.

IssueDetail & filters

Click any card to open the IssueDetail modal: markdown body, acceptance-criteria checklist, assignee inline editor, dependency lists (blocks / blocked-by), linked workspace pill, full status grid, and an inline comment thread + composer.

Above the board, IssueFilterChips give you multi-select popovers for Label / Epic / Workspace / Assignee, with a type-ahead filter when there are more than 6 options. A search box does full-text across titles and descriptions.

Acceptance-criteria caveat: once added, criteria cannot be edited — only deleted and re-added. Dependency cycles are not auto-detected, so avoid manually creating loops.

Code Quality & AutoFix

The Code Quality modal (Toolbar Quality button) runs lint, typecheck, test, build, and audit checks live — per-check tabs with sticky status badges, ANSI-rendered output, last-5-runs history, and AI explain / autofix hooks. v0.8.7

Live check runner

The backend quality_runner.rs spawns each check with kill_on_drop, a 3 s path probe + 300 s run timeout, and streams output via quality:chunk:{run_id}, quality:check-start, quality:check-done, and quality:done events. The cancel_quality_run command lets you abort cleanly.

Frontend per-check tabs render with sticky status badges — idle queued running passed failed cancelled skipped errored — and an in-house ANSI renderer (no new deps) with SGR + 256-color + truecolor support. Lines are filterable; path:line:col rows are click-to-copy.

Run history dropdown keeps the last 5 runs, keyed on normalized project path. Fullscreen toggle. Ctrl+R to refresh. Ctrl+F for filter focus. Esc to close.

AutoFix integrations

The code_quality_autofix.rs command wires four canonical fixers behind confirm modals:

  • ESLint → eslint --fix
  • Prettier → prettier --write
  • Rust → cargo fix
  • pnpm audit → pnpm audit --fix

Each streams via quality-fix:chunk:{run_id}. After a fix completes, an re-analyze nonce chain refreshes the modal so you immediately see the updated counts. A duplicate-run-id rejection registry plus cancel_quality_fix prevents the dreaded "double-click sent two fixes" footgun.

AI explain & summary

Three AI affordances per check:

  • Explain — per-error streamed Markdown explanation. Anti-injection envelope on every user-supplied tool output (XML-ish tags + system-prompt warning); per-check + total byte caps with two-pass shrink.
  • Fix in Workspace — creates a backlog Issue, provisions an issue-bound worktree, spawns a Claude pane seeded with the error context.
  • File Issue — one-click ticket creation, labeled lint / typecheck / test-failure / build based on the check kind.

Below the per-check tabs, a bottom-of-modal AI summary generates a digest of the whole run. A run-hash cache keys results by content, with clear-by-hash (not full wipe) so you can refresh selectively.

Remote workspaces: Code Quality is local-only. Pointing at a remote workspace surfaces a "not yet supported on remote workspaces" placeholder and the toolbar Quality button is disabled with an explanatory tooltip.

MCP Servers

Project
Lands in ./.mcp.json at the project root. Available to this project only.

The pencil icon reopens the modal for edits (name is locked once created). Disabled servers show a badge. The trash icon deletes with a confirmation.

MCP Provider

The Provider card is a readiness / configuration surface for exposing PacketADE-owned resources through MCP. Today it persists the enabled state, port, scope, resource catalog, and per-tool allow list in the frontend store. Chapter 16

Voice Input

The Dictation module is a full voice-to-text workspace: push-to-talk anywhere with Ctrl+Shift+V, native Whisper transcription, focus-aware insertion, and an analytics dashboard.

Native vs Web Speech

PacketADE checks for local Whisper models on startup via listWhisperModels(). If any model is present, the dictation hook flips into native mode. Otherwise it falls back to the browser Web Speech API. Recognition is locked to en-US.

Native is more accurate; Web Speech is the fallback. Native dedupe may collapse rapid repeated digits; the Web Speech path does not.

Hotkeys & focus-aware insertion

All four dictation hotkeys (push-to-talk, toggle, open view, cancel) are registered as OS-level global shortcuts via tauri-plugin-global-shortcut. Push-to-talk works even when PacketADE is not the focused application. In-window listeners are kept as a fallback for cases where OS registration is denied (e.g., macOS Accessibility permission not granted).

PacketADE tracks the most recently focused text input across every view. When transcription finishes and Auto-paste after transcription is on (default), the result is inserted at that input's cursor — agent chat box, flight title, issue description, prompt library, or anywhere else you've typed recently. Terminal panes and the Dictation view's own search box are deliberately excluded.

If you dictated from another app via the global hotkey and no PacketADE input was tracked, the transcript falls back to the system clipboard.

Analytics dashboard

The Dictation view surfaces Total Words, Avg WPM, Fastest WPM, Avg Sentiment, Total Time, Entries, Daily Streak, an estimated Time Saved, and a Vocab Diversity score. Charts: Sentiment over Time (bar), WPM over Time (line), Activity by Hour (histogram), Top Words (frequency), Words per Entry (distribution).

The hotkey bindings are user-rebindable. v0.8.1 In Settings → Dictation, click any hotkey to enter capture mode; Esc cancels; modifier required for validity. useDictationGlobalShortcuts re-registers on change.

import { Zap } from "lucide-react";

Architecture Overview

For contributors: a fast tour of how the pieces hang together. PacketADE is a Tauri v2 desktop app with three runtimes — React 19 frontend, Rust backend, Node sidecar — and a PTY layer for terminal-based CLIs.

The stack

Desktop shell
Tauri v2 (Rust). Custom dark theme, custom titlebar on Win/Linux, native traffic lights on macOS.
Frontend
React 19 + TypeScript + Vite. Zustand for state (persisted to localStorage under packetade:*; legacy packetcode:* read for migration only).
Styling
Tailwind with custom dark theme tokens (bg-bg-primary, text-accent-green, etc.). Never raw Tailwind colors.
Terminal
xterm.js + portable-pty. PTY-only session model — the legacy JSONL session stack was removed.
Backend
Rust. Tauri commands under src-tauri/src/commands/, registered in lib.rs. TypeScript bindings in src/lib/tauri.ts.
Sidecar
Node (TypeScript) in agent-sidecar/. Bundled with the installer; pinned Node 24.15.0 for the host triple.

Data flow — an API agent turn

  1. User types into AgentInputArea. Hits Enter.
  2. Frontend pre-allocates a session ID, attaches Tauri listeners on api-agent:chunk:{id}, :tool-start:{id}, :tool-result:{id}, :done:{id}, :error:{id} BEFORE invoking the backend.
  3. start_api_agent_session (Rust) routes the request: API-key providers go in-process via LlmProvider; OAuth providers go to the Node sidecar.
  4. Backend streams chunks back as Tauri events. agentTaskStore on the frontend reduces them into the conversation state.
  5. On permission-request or pending-edit, findTaskBySessionId looks up any linked Mission task and flips it to approval_needed — the Bell badge updates.
  6. On done, usage is written to ~/.packetade/usage.jsonl; the conversation JSON is persisted to ~/.packetade/conversations/{id}.json (debounced 500 ms).

Event contract

Backend features emit scoped Tauri events; the frontend listens via @tauri-apps/api/event. Event names are feature-scoped to avoid collisions:

  • api-agent:{kind}:{sessionId} — the canonical agent stream (Chapter 5).
  • insights:chunk / :done / :error — Insights chat.
  • flight-chat:chunk / :done — New Mission planner chat (separate from Insights to avoid collision).
  • side-chat:chunk — the SideChatOverlay.
  • quality:chunk:{run_id} + quality:check-start / :check-done / :done — Code Quality runner (Chapter 11).
  • quality-fix:chunk:{run_id} — Code Quality AutoFix.
  • issue-watcher:fixed — trailer parser fired (Chapter 7).
  • provider-auth:changed — ~/.claude or ~/.codex mutation.
  • sidecar-status:changed — supervisor lifecycle.

Remote Agents Roadmap

Remote Agents is the next major PacketADE track: a PWA-first way to use PacketADE Agents from a phone while the desktop keeps ownership of providers, models, secrets, MCP config, workspaces, permissions, and execution.

Scope

The first release focuses on API-agent conversations, not raw terminal control. From the PWA, a trusted device should be able to list hosts, workspaces, providers, models, profiles, and conversations; start or continue an API-agent conversation; stream existing api-agent:* events; respond to permission or edit prompts; cancel, retry, change model, close; and observe cost/status summaries.

Remote Agents deliberately does not expose a generic Tauri bridge. New remote actions require explicit protocol commands and security review.

Security model

Packet account sign-in
The primary phone flow is account sign-in. QR may become a shortcut later, but it is not the main trust path.
Desktop trust gate
A desktop host must approve a device before the PWA can control sessions. Revocation and audit trails are part of the MVP.
Desktop-owned secrets
Provider keys, OAuth tokens, local files, shells, MCP servers, and SSH access remain on the desktop. Packet Cloud relays frames; it does not call model providers or tools.
End-to-end encryption
E2EE, replay protection, sequence validation, and protocol fixtures are gates before any external beta.
Push boundaries
Foreground interaction is WebSocket. Web Push is only for attention-needed notifications such as permission requests, pending edits, errors, and done summaries.

Status

Planning is complete and ready for implementation split. The canonical implementation package lives in dev/remoteagents/README.md, with product scope, architecture, protocol, security, PWA UX, sprint plan, six-agent runbook, testing, and open decisions. The top-level summary is in the public roadmap.

Availability: Remote Agents is not in the current desktop release. It is the active roadmap track after the docs/planning consolidation.

Glossary

Workspace
A project folder PacketADE has opened. Sessions, missions, issues, and memory are scoped per workspace.
Session / Pane
A single running PTY pane inside a workspace — a shell, CLI agent, or terminal process.
Mission (Flight)
User-facing: a Mission. Internal types still say "Flight". The top-level planning unit; one Sonnet 4.6 planner owns it end-to-end.
Attempt
One executor agent run for one task inside a Mission. Multiple attempts can exist per task on retry.
Agent profile
A saved configuration of system prompt, allowed tools, and default model. Reusable across conversations.
API agent
A conversation driven through a provider's API by the in-process Rust agentic loop or the Node sidecar.
CLI agent
A conversation driven through a locally-installed vendor CLI (claude, codex, etc.) in a PTY.
Sidecar
The bundled Node runtime that hosts the Claude Agent SDK and Codex exec providers. JSON-over-stdio.
Memory
The persistent, project-scoped store of session summaries, learned patterns, and manual notes.
Worktree
A git worktree provisioned per Mission attempt or per Issue. Lets executor agents work in isolation without stomping main.
Bypass permissions
The toggle that suppresses CLI permission prompts for write tools (e.g. Claude's --dangerously-skip-permissions).
FlightDeck
The sibling terminal-first product at d:\projects\flightdeck. Mirrors the same Mission concepts; separate repo, separate git history.
PacketCode
The sibling TUI product (OpenCode rival) at d:\projects\packetcode. Not the same as this product, despite the legacy name.
Remote Agents
The planned PWA + Packet Cloud relay track for controlling PacketADE API-agent conversations from a trusted phone while execution and secrets stay on desktop.
