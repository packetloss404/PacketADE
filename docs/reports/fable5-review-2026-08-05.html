03

Area scorecards

Rust backend

B / B+
  • Security engineering is genuinely strong: correct shell-quoting at all ~15 remote builders, symlink-canonicalizing sandboxes on both local and SSH paths, secrets never in argv/env/logs.
  • All 240 commands registered and called-or-catalogued; deploy.rs/ideation.rs orphans are gone; near-zero TODO density.
  • Weak spots: process lifecycle (F4/F5), lock fairness (F10), a symlink-following grep, a sub-agent dispatch that routes around DenyAll, and zero tests on the MCP write-gate surface.

Sidecar & build pipeline

B
  • Control flow and bundling order are correct; Anthropic credential handling verified careful (OAuth token blanked, no ambient fallback, adversarial test).
  • The weakness is uniform: the pipeline verifies existence and self-consistency, never content or upstream authenticity (F8/F9); several smoke tests are tautologies.
  • Both agent SDKs are pinned to ranges that can never resolve forward — upgrade deliberately after landing the missing cancel/429 tests.

Flight Deck

Fix before flagship
  • Architecture is sound and most documented invariants verified as holding; the planner amputation left no residue.
  • But the Reviewer Gate is dead on arrival (F1), Accept doesn't land code (F2), restart leaks attempts (F3), and cost deltas can double-count permanently.
  • Bounded-YOLO hard stops and the cooperative graph verified real; the claimed CI8 routing adapter never landed — doc corrected.

Frontend

B
  • State layer and conventions are strong: 57 stores with sound boundaries (no merges recommended), safe storage migration, disciplined theme tokens.
  • One bug shape — unlisten assigned after await — repeats across eight files; a five-file mountedRef slip breaks PR/quality panels in dev; four theme tokens are used but undefined (real colourless UI today).
  • ~2,483 LOC of event runtimes are filed under stores/ — exactly the untested code; coverage is not measured at all.

Documentation

B+ → A−
  • The markdown planning set held up to adversarial checking: zero broken links across 76 files, test counts verified, honest in both directions.
  • The public GitHub Pages site was two releases stale and advertised removed features — repaired during this pass with grep-proof.
  • CHANGELOG gap (the 08-01 correctness pass), index orphans, and a rogue second backlog all fixed; research layout deliberately left as-is.

Release readiness

GO, conditional
  • The installer has never been run — every "packaged" claim means the bundler produced a file. First install is scheduled day 5, not day 13.
  • Signing identity is the critical path; the updater client should ship in 1.0 (a one-way door) with the first served update in 1.1.
  • 19 of 24 released versions have no git tag; version parity across the three manifests is clean.

Phase 1Aug 5 – Aug 7

Unblock the long pole

Cert applications in the first hour. Updater keypair generated (after *.key hits .gitignore) and backed up twice. Release-gate script defects fixed, dead CSP origin removed, updater client wired, 19 missing tags backfilled. Full pnpm check ladder including Playwright — never run in any release. Phase 2Aug 10 – Aug 14

Actually install the thing

1.0.0-rc1 build, then the first-ever installer run on Monday. Acceptance matrix Mon–Wed with the bundled-sidecar conversation first (highest packaging risk), then shells, statusline, a Flight end-to-end, keyring, Monitor. Wed–Fri is reserved fix buffer — protect it.

Phase 3Aug 17 – Aug 19

Ship

Final signed build with .sig files, clean-machine install, UAC publisher verified, dev/release-v1.0.0.md in the established format, annotated tag, GitHub Release with hashes, docs synced.

Contingency: if the certificate hasn't arrived by Aug 17, ship the artifact publicly as v1.0.0-rc1, unsigned, with hashes — and hold the v1.0.0 tag for the signed build. Don't spend the 1.0 moment on an unsigned artifact.
