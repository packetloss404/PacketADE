## 0. ORIENTATION

**What it is.** PacketBench is a single-user Tauri v2 desktop app (`src-tauri/tauri.conf.json`,
identifier `com.packetbench.desktop`, version 0.13.2). A React 19 webview talks to a Rust
backend over Tauri IPC (254 `#[tauri::command]` handlers registered in `src-tauri/src/lib.rs:196-360`).
The Rust side spawns PTY-backed coding CLIs (`claude`, `codex`, `opencode`, `packetcode`, shells,
`ssh`) and runs "API agents" — an in-process LLM tool loop (`src-tauri/src/commands/api_agent.rs`)
for Anthropic/OpenAI/MiniMax/OpenRouter/Ollama/custom endpoints, plus a Node sidecar
(`agent-sidecar/`) that hosts the Claude Agent SDK and OpenAI Agents SDK over stdio JSON
(protocol v11, `src-tauri/src/commands/agent_sidecar/mod.rs:109-119`).

**What it deploys to.** Nothing hosted. It ships as NSIS/MSI installers built locally by
`pnpm tauri build` (`scripts/release-gate.mjs`, `dev/beta-distribution-trust-runbook.md`). There
is no CI by design (`dev/local-quality-gates.md:3`), no updater (`dev/updater-setup.md:5-10`),
no code signing (deferred on cost, `HANDOFF.md` "Context"). The `.dockerignore` at the root
referenced a `scripts/build-docs.mjs` and `docs/` tree that do not exist — dead config, removed
in P11. The one server-side component, the PacketRelay for Remote Agents, lives in a sibling
repo (`D:\projects\packetrelay`) and is out of scope; in this repo Remote Agents is a 51-line
PWA skeleton with no network code (`remoteagents/pwa/src/App.tsx`) behind a default-off flag
(`src/stores/remoteAgentsSettingsStore.ts:16`).

**Who can reach it.** Inbound network surface is exactly one thing: the optional MCP server,
bound to `127.0.0.1` only (`src-tauri/src/mcp_server/transport.rs:43`), started from the UI,
bearer-token + Origin guarded. Everything else is outbound: LLM providers, GitHub/Gitea/GitLab,
the PacketAgent service (user-configured HTTPS endpoint), Ollama, Hugging Face (whisper models),
and SSH to user-configured servers. Local processes on the same machine are the only "other
users": the PTY children, MCP stdio servers, hooks, and the sidecar.

**Trust boundaries that actually matter** (the IPC boundary is NOT one — the webview is the
app's own code under `script-src 'self'`, and no raw-HTML rendering path exists):

1. Untrusted content reaching the model: `web_fetch` results, GitHub issue/PR bodies via `gh_*`
   tools, files in the repo, MCP tool output, PacketAgent SSE events. A prompt-injected model then
   calls tools. This is the boundary most findings live on.
2. Repo-supplied executables: `<project>/.claude/settings.json` hooks, `<project>/.mcp.json`
   servers, `<project>/.claude/agents/*.md`. Before this audit nothing gated them.
3. The loopback MCP server: any local process or browser page that can reach 127.0.0.1.
4. Remote services the app authenticates to with secrets from the OS keyring.

**What is unfinished** (detail in §5): GitHub device-flow OAuth is dead code in stock builds
(`GITHUB_OAUTH_CLIENT_ID` is `""`); Remote Agents is Sprint-0 scaffolding; the sub-agent tool
allowlist was advisory (fixed, P03); `tool_tasks.rs` task state is process-global across
sessions; Windows password-auth SSH writes the password to stdin, which OpenSSH does not read;
"Show in Explorer" and "Open in VS Code/Cursor" were blocked by the shell plugin's default
open-scope regex (P10 fixes the URL-scheme half).

**Guesses to correct me on:**

- G1. I treated the app as single-user on a machine the user controls, so "IDOR" on IPC ids is
  not a class of finding; the sections say "checked, n/a" where that applies.
- G2. I assumed no one runs `pnpm dev` (Vite 6.4.1 dev server, two file-read CVEs) exposed on a
  LAN. If you do, treat the dependency snapshot's Vite row as high.
- G3. I assumed the `main` branch is what ships. `HANDOFF.md` mentions a
  `feat/quality-gates-pty-outcomes-durable-state` branch; `git worktree list` shows only `main`.
- G4. I assumed `~/.claude/settings.json` (not `~/.claude.json`) is the intended global MCP store
  because every reader in this repo uses it. Claude Code itself stores user-scope MCP servers in
  `~/.claude.json`, so entries written by PacketBench's MCP Hub are invisible to Claude Code.
  Reported as a correctness note, not patched.
- G5. I chose `~/.packetbench/trusted-projects.json` as the trust list location (P01) because
  it needed no DTO/schema change and travels with a data-dir backup. If you want it in Settings UI,
  that is the follow-up task in the handoff.

**Data stores** (all under `~/.packetbench/` unless noted): `state.v1.json` (flights, workspaces,
issues, servers, settings, memory; atomic write with `.bak`, `core/storage.rs:1067-1113`),
`provider-settings.json`, `webview-storage-mirror.json`, `conversations/<id>.json`,
`usage.jsonl` (cost ledger), `dictation/` SQLite, `models/ggml-*.bin`, `ssh/known_hosts`,
`crashes/crash-<ts>.log`, `scratch/`, `trusted-projects.json` (new, P01). Secrets: OS keyring
only (`api-key-<provider>`, `github-token`, per-connection git-host tokens, `ssh-<serverId>`,
`packet-agent-token`). Logs: `%LOCALAPPDATA%\PacketBench\logs\packetbench.log.<date>`
(`lib.rs:37-65`, daily rolling, level from `RUST_LOG`, default `info`).

**Background jobs**: PTY reader threads; agent loops (`tokio::spawn`, cancellable); sidecar
supervisor with 3-restarts-per-60s cap; PacketAgent SSE consumers with backoff; auth-credential
fs watcher (`auth_watcher.rs`); project-memory fs watcher; cost-guardrail poller in the webview
(`src/lib/bootstrap.ts:239`); no cron, no queue.

**Config / secret loading**: no `.env`. Runtime env overrides are `PACKETBENCH_*`
(full list in `core/boot_check.rs`, P09). Provider base URLs and Ollama options come from
`provider-settings.json` with `PACKETBENCH_OLLAMA_URL` / `PACKETBENCH_MINIMAX_URL` /
`PACKETBENCH_CUSTOM_COMPAT_URL` overrides (`core/storage.rs:847-1066`). Keys are loaded per
call from the keyring (`commands/api_keys.rs:119`), handed to the sidecar inside the
`start_session` JSON (`api_agent.rs:1057-1061`), never via environment or disk.

the invoke guard in `lib.rs:129-147` rejects any window other than `main` unless the command is
in `MONITOR_ALLOWED_APP_COMMANDS`. There are no user accounts and no roles in the product; the
two "roles" are the `main` window and the read-only `monitor-*` window. `bearer` = MCP bearer
token minted per server start. IDs are referenced by later sections.

+//! Project trust: which repositories may supply code that PacketBench runs.
+//!
+//! Three repo-controlled files can cause PacketBench to execute something on
+//! the user's machine the moment a conversation starts in that repo:
+//!
+//! - `<project>/.claude/settings.json` `hooks` — run through `sh -c` /
+//!   `cmd /C` on SessionStart, PreToolUse, PostToolUse, SessionEnd
+//!   (`core::hooks`).
+//! - `<project>/.mcp.json` `mcpServers` — stdio servers spawned by the sidecar
+//!   for Agent SDK sessions (`commands::api_agent::build_mcp_config_for_sidecar`).
+//! - `<project>/.claude/agents/*.md` — sub-agent definitions whose prompt and
+//!   tool list are advertised to the model (`commands::custom_agents`).
+//!
+//! None of those carried a trust decision: cloning an untrusted repository and
+//! opening a conversation was enough. This module is the single fail-closed
+//! gate. A project is trusted only when its canonical path is listed in
+//! `<data dir>/trusted-projects.json`:
+//!
+//! ```json
+//! { "version": 1, "projects": ["D:\\projects\\PacketBench", "/home/me/app"] }
+//! ```
+//!
+//! Anything that cannot be read, parsed, or canonicalized is untrusted. There
+//! is deliberately no environment-variable override: a repo-supplied shell
+//! command is exactly the kind of thing an env var must not be able to enable.
+
+use std::path::{Path, PathBuf};
+
+use serde::{Deserialize, Serialize};
+use tracing::{info, warn};
+
+pub const TRUSTED_PROJECTS_FILE: &str = "trusted-projects.json";
+
+#[derive(Debug, Default, Serialize, Deserialize)]
+struct TrustedProjectsFile {
+    #[serde(default)]
+    version: u32,
+    #[serde(default)]
+    projects: Vec<String>,
+}
+
+/// Absolute path of the trust list. Lives beside `state.v1.json` so a
+/// data-dir backup or restore carries the trust decisions with it.
+pub fn trusted_projects_path() -> PathBuf {
+    crate::core::storage::data_dir().join(TRUSTED_PROJECTS_FILE)
+}
+
+fn canonical(path: &Path) -> Option<PathBuf> {
+    std::fs::canonicalize(path).ok()
+}
+
+fn read_trusted_projects(path: &Path) -> Vec<PathBuf> {
+    let raw = match std::fs::read_to_string(path) {
+        Ok(raw) => raw,
+        Err(e) if e.kind() == std::io::ErrorKind::NotFound => return Vec::new(),
+        Err(e) => {
+            warn!(
+                target: "packetbench::trust",
+                path = %path.display(),
+                error = %e,
+                "trusted-projects file unreadable; treating every project as untrusted"
+            );
+            return Vec::new();
+        }
+    };
+    let parsed: TrustedProjectsFile = match serde_json::from_str(&raw) {
+        Ok(parsed) => parsed,
+        Err(e) => {
+            warn!(
+                target: "packetbench::trust",
+                path = %path.display(),
+                error = %e,
+                "trusted-projects file is not valid JSON; treating every project as untrusted"
+            );
+            return Vec::new();
+        }
+    };
+    if parsed.version != 1 {
+        warn!(
+            target: "packetbench::trust",
+            path = %path.display(),
+            version = parsed.version,
+            "trusted-projects file has an unsupported version; expected 1"
+        );
+        return Vec::new();
+    }
+    parsed
+        .projects
+        .iter()
+        .filter_map(|entry| {
+            let trimmed = entry.trim();
+            if trimmed.is_empty() {
+                return None;
+            }
+            let path = Path::new(trimmed);
+            if !path.is_absolute() {
+                warn!(
+                    target: "packetbench::trust",
+                    entry = %trimmed,
+                    "trusted-projects entry ignored: not an absolute path"
+                );
+                return None;
+            }
+            match canonical(path) {
+                Some(canonical) => Some(canonical),
+                None => {
+                    warn!(
+                        target: "packetbench::trust",
+                        entry = %trimmed,
+                        "trusted-projects entry ignored: path does not resolve"
+                    );
+                    None
+                }
+            }
+        })
+        .collect()
+}
+
+/// Pure decision: is `project_path` one of the trusted canonical roots?
+/// Comparison is by canonical path so `D:\a\..\b` and a symlink to the same
+/// directory count as the same project. A project inside a trusted root is
+/// NOT trusted by inheritance — a repo cloned under a trusted parent is still
+/// a different repo.
+pub fn is_trusted_in(project_path: &str, trusted: &[PathBuf]) -> bool {
+    if project_path.trim().is_empty() || trusted.is_empty() {
+        return false;
+    }
+    let Some(canonical_project) = canonical(Path::new(project_path)) else {
+        return false;
+    };
+    trusted.iter().any(|root| root == &canonical_project)
+}
+
+/// Whether repo-supplied executables (hooks, `.mcp.json` servers, project
+/// agent definitions) may run for `project_path`. Fail-closed: any read,
+/// parse, or canonicalization failure is `false`.
+pub fn is_project_trusted(project_path: &str) -> bool {
+    let path = trusted_projects_path();
+    let trusted = read_trusted_projects(&path);
+    let decision = is_trusted_in(project_path, &trusted);
+    if !decision {
+        info!(
+            target: "packetbench::trust",
+            project = %project_path,
+            trust_file = %path.display(),
+            "project is not trusted: repo-supplied hooks, .mcp.json servers, and .claude/agents are ignored"
+        );
+    }
+    decision
+}

+//! Boot-time configuration validation.
+//!
+//! PacketBench has no `.env` and almost no required configuration — most
+//! settings are chosen in the UI and stored in the data dir or the OS
+//! keyring. What CAN silently break a fresh install or a dark-period restart
+//! is environmental: an unwritable data dir, a credential store that refuses
+//! every read, a typo'd `PACKETBENCH_*` override, or a developer override that
+//! points at a file that is no longer there. This module checks each once at
+//! startup and logs one line per check under the `packetbench::boot` target,
+//! naming the exact variable or path involved. It never aborts startup: the
+//! app still opens so the user can read the message in the log or the UI.
+//!
+//! Log file: `%LOCALAPPDATA%\PacketBench\logs\packetbench.log.<date>` on
+//! Windows, `~/Library/Application Support/PacketBench/logs/` on macOS,
+//! `$XDG_DATA_HOME/PacketBench/logs/` on Linux (see `lib.rs::dirs_log_dir`).

+/// Pure classification of the process environment; separated from `run` so
+/// it is unit-testable without touching the real environment.
+pub fn classify_env(vars: &[(String, String)], file_exists: &dyn Fn(&str) -> bool) -> Vec<BootIssue> {
+    let mut issues = Vec::new();
+    for (name, value) in vars {
+        if !name.starts_with("PACKETBENCH_") {
+            continue;
+        }
+        if !KNOWN_ENV_VARS.contains(&name.as_str()) {
+            issues.push(BootIssue {
+                check: "env",
+                message: format!(
+                    "{name} is set but is not a variable PacketBench reads (typo? known: {})",
+                    KNOWN_ENV_VARS.join(", ")
+                ),
+            });
+            continue;
+        }
+        if FILE_PATH_ENV_VARS.contains(&name.as_str()) && !file_exists(value) {
+            issues.push(BootIssue {
+                check: "env",
+                message: format!("{name}={value} does not point at an existing file"),
+            });
+        }
+    }
+    issues

### P15 — Make the Remote Agents flag actually fail closed (F23)

File: `docs/audit/patches/P15-remote-agents-fail-closed-gate.diff`

Written on owner request after the `d6238633` re-read surfaced the gap. This is deliberately **not** finishing the
feature — H02 still says leave Sprint 0 scaffolding alone. It builds the gate that Sprint 1 has to pass, and
nothing else. No Settings toggle was added, because a toggle is feature work and would also be the exact surface

Four properties, each chosen so the failure mode is refusal rather than silence:

1. **The gate list is transcribed, not invented.** Eleven entries, verbatim from the "Private beta gate" in
   `dev/remoteagents/04-security.md:385-397` — the list the E2EE decision (`09-open-decisions.md:285`, resolved

`requested` (a bare `.enabled` no longer type-checks), and an eslint `no-restricted-imports` **pattern** group bans

specifier differs by import depth; both the `@/stores/...` and `../stores/...` forms were verified to error.

### P16 — Every storage key through `storageKey()` (F24)

File: `docs/audit/patches/P16-storage-keys-through-brand.diff`

Found while auditing the rest of the Sprint 0 window on owner request. The other six Remote Agents Sprint 0
commits (`c02fbc17`, `5f1375ca`, `43503d77`, `581625d2`, `9bafbff2`, `c4d2ba88`) are **documentation only** —
zero `.ts`/`.tsx`/`.rs`/`.mjs`/`.json` files between them — so the F20–F22 gap class cannot exist there. The rename
`5404fb85` sits in the same window and IS a call-site enumeration, which is where the same gap turned up at scale.

The conversion is mechanical and safe by construction: `storageKey(s)` is `STORAGE_PREFIX + s` (`brand.ts:28-30`),
so each key is byte-identical to the literal it replaces. The evidence is not the arithmetic, though — it is that
the full suite passes unchanged, and a dozen of those tests assert the literal `packetbench:*` strings
(`persistenceMigration.test.ts`, `storageMirror.test.ts`, `mcpProviderStore.test.ts`, `promptStore.test.ts`, …).
Any drift would have turned them red.

Two things the fence caught that a manual sweep had misfiled:

- Seven MCP resource URIs in `mcpProviderStore.ts` (`packetbench://issues`, `packetbench://flights/${id}`, …).
  These are `URI_SCHEME`, not `storageKey` — a different brand constant for a different namespace. Three were
  double-quoted and four were template literals; a regex written for the quoted form alone would have missed the
  second half, which is why the fence runs against the tree rather than against a list.
- `layoutStore.ts:75` wrote `packetbench:workspaces-cache` inline while `workspaceStore.ts:326` defined
  `WORKSPACES_CACHE_KEY` for the same key. Both now derive from the prefix. They are deliberately NOT
  cross-imported: that would couple the layout engine to the workspace engine, which the tile-program store
  isolation exists to prevent. The suffix is still written twice, with a comment on each side.

The fence itself is the durable part. `scripts/storage-key-brand.test.mjs` fails on any new hardcoded prefix, and
a second test fails on a **stale allowlist entry** — an exemption whose file no longer contains the prefix — so the
exemption list cannot quietly become a list of things nobody rechecked. Five files are exempt and each is a DOM
`CustomEvent` name, an identifier, or the definition itself; none is a storage key, and for those a rename cannot
desynchronise the two sides because both already read one exported constant.

Verified: `pnpm gates:fast` all PASS (format, lint, typecheck, and the full vitest suite).

cosmetic change that would touch assertions on literal text in component tests, and it carries none of the
data-loss risk that made the storage keys worth fixing. Left as a note rather than folded into a persistence

### P17 — User-visible copy through `APP_NAME` (F25)

File: `docs/audit/patches/P17-ui-prose-through-app-name.diff`

Written on owner request, having flagged it as deliberately-left under P16. Mechanically safe for the same reason
P16 was: `APP_NAME` is `"PacketBench"`, so every rendered string is byte-identical, and the component tests that
assert on-screen text pass unchanged.

The work was in deciding what NOT to convert, and a dry-run preview caught four things a blind sweep would have
broken:

1. **A JSX comment.** `PermissionPrompt.tsx:336` sits inside `{/* … */}`. The first pass rewrote it, because the
   comment check only knew `//`, `*` and `/*`. Fixed with real block tracking.
2. **A GitHub URL.** `ToolsView.tsx:659` links to

   follow a product rename — `CLAUDE.md` even notes the old `PacketADE` URL still redirects. Interpolating
   `APP_NAME` there would break the releases link at the next rename. Excluded.
3. **Then the URL again, differently.** Once the string pass skipped it, the JSX-text pass rewrote the bare word
   *inside* the URL, which was worse. The JSX pass is now quote-aware and only touches text outside a quoted span.
4. **`? "PacketBench"`** became `` ? `${APP_NAME}` ``, a template wrapping one value. Now emits bare `APP_NAME`.

Three sites stay literal, and this is the substantive judgement in the patch:

- `src/lib/tauri.ts:2375` and `src/stores/orchestrationSettingsStore.ts:12` hold the `Run-By: PacketBench flight
  F-{flightId} attempt A-{attemptId}` trailer template. The identical literal lives in
  `src-tauri/src/core/orchestrator.rs:10`, it is written into git commit messages that already exist in history,
  and it is matched by a glob inside a generated git hook shell script (`src-tauri/src/core/worktree.rs:508,580`).
  Making only the TypeScript half dynamic would let the two diverge at the next rename — worse than leaving both
  literal. Rename it on both sides deliberately, or not at all.
- `src/lib/brand.ts:10` is the definition.

One process note worth recording. The first application also ran `prettier --write` over every touched file, which
reformatted unrelated code and turned a 63-line change into a 686-insertion / 679-deletion diff — `format:check`
does not cover `src/`, so those files had never been prettier-formatted. That was reverted and redone without it;
the patch is 106 insertions / 64 deletions. A branding patch that also silently reformats a store is not
reviewable, and a diff nobody can review is where regressions hide.

Verified: `pnpm gates:fast` all PASS; both brand fences pass.
