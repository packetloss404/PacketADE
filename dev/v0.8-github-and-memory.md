1. PR actions: merge / close / reopen / convert-to-draft

3. Issue commenting + state controls: comment composer, close/reopen, assignee picker, labels, milestone
4. Closed/All state filters on issues and PRs
5. Pagination ("showing N of M" + load-more) on issues, PRs, repos

   - **Plan flight** → handoff to Flight Planner spec mode with issue body as the opening user turn

   - **Hand off to Claude** → open a `claude-code` PTY session with the AI investigation as context

### Flight Planner ↔ GitHub (Tier 4 — integration)

### Memory pane (Tier 5)

## What's out of scope (defer to v0.9 / v1.1)

- Helper planner (v1.1 already)
- Release management / gist creation / actions runs view
- The `gh` CLI auth flow / OAuth device flow (token-paste stays for now)
- "Ask your project" memory chat tab
- 30-day memory digest

## Architecture conventions

### AI features
- One-shot `api-claude-oauth` sidecar session per call, mirror the existing `github_investigate_issue` pattern in `src-tauri/src/commands/github.rs`
- All hand-authored prompts live in a new module `src-tauri/src/core/github_ai_prompts.rs`. Move the existing `github_investigate_issue` prompt there too.
- Stream chunks via the existing `api-agent:*:<sessionId>` event channels
- Cache the rendered output keyed on the input hash where it makes sense (PR description re-runs on the same diff should not re-burn quota)

### Tauri commands
- One command per resource action: `github_merge_pr`, `github_close_pr`, `github_reopen_pr`, `github_convert_pr_to_draft`, `github_get_pr_checks`, `github_comment_on_issue`, `github_close_issue`, `github_reopen_issue`, `github_assign_issue`, `github_label_issue`, `github_milestone_issue`, etc.
- AI commands: `github_ai_pr_description`, `github_ai_pr_review`, `github_ai_catch_up`, `github_ai_triage`
- Register each in `lib.rs::generate_handler!`

### Frontend file structure
- New folder `src/components/views/github/` for extracted GitHubView subcomponents
- One file per logical section: `PRDetail.tsx`, `PRActionBar.tsx`, `PRChecksTab.tsx`, `IssueDetail.tsx`, `IssueActionBar.tsx`, `IssueCommentList.tsx`, `IssueCommentComposer.tsx`, `AIInvestigateActions.tsx` (for the 3 buttons), `AICatchUpButton.tsx`, `AITriageDrawer.tsx`, `PRDiffWithChecks.tsx`
- `GitHubView.tsx` becomes a thin orchestrator that composes the subcomponents

### Memory inline surfaces
- New files in `src/components/missions/` and `src/components/agents/` and `src/components/workspace/` as appropriate
- Don't bloat MemoryView — surface FROM the same memoryStore selectors

- Schema regen via `pnpm generate:tauri-schema` must run after all backend agents finish
