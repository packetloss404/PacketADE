# Conversation-as-Tile Design Spec — Two-Team Consensus (2026-07-08)

> **SUPERSEDED PRODUCT DIRECTION (2026-07-29).** This is retained as historical
> design rationale only. PacketADE now keeps Agents as the first-class
> same-window GUI-agent surface, makes Workspace CLI/PacketCode-first, creates
> no new Workspace conversation panes or wrapper Workspaces, and preserves the
> tile renderer only for old saved layouts. The canonical direction is
> [`workspace-agents-restructuring-goal.md`](../workspace-agents-restructuring-goal.md).

Produced by a 15-agent two-team design pass (Alpha: product-design lens; Bravo: staff-engineering lens) with cross-examination, defense, and moderator synthesis. Prerequisite context: the completed 20-item consolidation program (dev/consensus-ux-consolidation-plan.md) and the 4-agent strategic panel that fixed the direction: the standalone Agents tab retires; the agent conversation becomes a workspace tile type; Workspaces become the single primary surface.

## Executive summary

PacketADE becomes a single-surface app: Workspaces is the one place you work, and the old Agents tab retires. The left sidebar becomes a fleet list of sessions — every agent you're running, API-driven or CLI, appears as one row, sorted so anything that needs your attention (a pending approval, a question) is pinned at the top with an amber count. A "session" is not a new database object; it is a read-only projection over the two engines that already exist (the API conversation store and the workspace/PTY store), unified into one five-word status vocabulary: needs-you, working, idle, done, failed. Nothing about the conversation engine changes — which is what keeps Flight Deck working and the Remote Agents roadmap item buildable on the exact same contract.

Inside a workspace, an agent conversation becomes a tile you can place next to terminal tiles in the mosaic. The tile's face is the chat itself — the same transcript, approvals, review bar, and composer that exist today, mounted unmodified inside a thin wrapper. Its slim header carries a drag grip, the agent's color, a status pill, a safety-mode chip, a changes count, and a zoom button. When you open the full review surface, the tile auto-maximizes using the existing CSS zoom (nothing remounts, so terminal sessions in sibling tiles survive — the hard lesson from the PTY work is law here). Adding an agent is one picker with two sections, "Chat agents" and "Terminals"; picking a chat agent drops in a draft tile where you set model, safety mode, and worktree right in the composer, then type your task.

Work finally ends in a commit. Today, conversation worktrees are unlandable — there is literally no merge, PR, or discard path in the app (we verified the cleanup function has zero callers). The design gives every workspace one git panel (the existing GitDashboard, scoped to whichever tile is focused) with a new lifecycle bar: Merge back (new squash-merge command, refuses on a dirty checkout), Create PR (extracted from the already-proven Flight Deck path), Discard, or Keep for later with a visible "worktree pending" badge. This fix, plus making Codex stop advertising approval modes its adapter can't honor, ships FIRST, in the existing Agents tab, so the two worst live bugs close even if the program pauses.

Existing conversations are never bulk-migrated. They appear as rows in the new sidebar automatically (a derived view); a real workspace record is created only when you open or touch one — so upgrade day rewrites nothing, downgrade stays safe (an old build shows a harmless placeholder tile and the new build self-heals it), and the sidebar the morning after reads like your old Agents list reorganized under projects, not like data loss. The Agents tab survives one release as an invisible redirect, then is deleted. Total: about 7.75 engineer-weeks — slightly above the panel's 5-7 anchor because roughly two weeks of it is repairing shipped bugs (unlandable worktrees, the Codex mode lie, blind commits) that the anchor never priced, stated plainly rather than hidden.

## Design answers

### Q1 — Unified session model

The unified session is a DERIVED PROJECTION, never a merged store — both teams converged here independently and it stands. agentTaskStore remains the headless conversation engine (the api-agent:\* contract is frozen: no event renames, no new start_api_agent_session params, createApiConversation options incl. explicitId/skipBackendStart byte-identical — Flight Deck at asyncFlightStore.ts:465-501 is the standing proof of headlessness). workspaceStore remains the placement container. New src/lib/sessionIndex.ts holds pure selectors projecting both stores into UnifiedSession rows (kind "pty"|"conversation") with ONE attention vocabulary: needs_you / working / idle / done / failed; it enumerates ALL conversations — placed, unplaced, AND archived (fixing Alpha's conceded archived-stranding hole) — and excludes Flight Deck attempt conversations via an attempt-sessionId lookup set (fixing Bravo's conceded sidebar-flooding hole). SCHEMA: WorkspacePane gains kind?: "terminal"|"conversation" (Bravo's discriminant won — Alpha conceded that overloading agentId leaks "conversation" into workspace.agents[], agentCounts badges, and override keys, verified at workspaceStore.ts:353/374 and WorkspaceView.tsx:79-84) plus conversationId?: string. Rust mirror is mandatory: #[serde(default)] kind/conversation_id on core WorkspacePane (precedent: task_id/flight_id, core/workspace.rs) + a Conversation DTO variant + threading through toDtoWorkspace/fromDto — I verified tauri.ts:1443-1449 whitelists exactly five pane fields, so unmirrored fields silently drop on save; the round-trip test is a Phase-1 gate. DOWNGRADE (moderator ruling for Alpha's mechanism): conversation panes persist agent_id:"terminal" as a documented inert carrier. Bravo's lazy version-stamp refusal is REJECTED on code evidence: workspaces live inside the single monolithic state.v1.json (storage.rs:67,102,110) whose version field is an optimistic-concurrency counter bumped on every save with no schema gate on load — any refusal mechanism would lock a downgraded binary out of the user's ENTIRE state, strictly worse than one benign shell tile. With the carrier, an old binary parses fine (From<String> hits the "terminal" arm, not the catch-all at api/mod.rs:741), renders a harmless terminal pane, drops kind/conversationId on re-save — and the new binary's reconciliation sweep re-pairs the orphaned conversation as an unplaced row: self-healing, no data touched. LIFECYCLE: src/stores/sessionGlue.ts owns one-directional GC (deleteConversation prunes referencing panes via removeConversationPanes; closing a tile never touches the conversation), an idempotent startup reconciliation sweep (replaces Alpha's withdrawn one-shot localStorage guard — no-op re-runs are not repair, reconciliation is), and openSession(); eslint no-restricted-imports enforces that neither store imports the other. Direction is pane→conversationId ONLY; AgentConversation never gains workspaceId (a legacy stale workspaceId key is already stripped from persisted conversation files at agentConversationPersistence.ts:23/151 — a named test now pins that strip). ONE new engine field: conversation.worktree {basePath, worktreePath, branch, baseBranch, createdAt, state: "active"|"landed"|"discarded"} — AttemptTarget-isomorphic (Bravo) with the explicit state enum (Alpha) — stamped at provisioning going forward in launchConversation.ts; legacy worktrees derive path/branch at the READ layer only, baseBranch:unknown with an explicit base picker (hydration-time persistence of derived fields is rejected as a bulk write). resumeToken/sshTarget/permissionMode/model stay on the conversation; sessionId stays PTY-only. normalizePanes() defensively normalizes the blindly-cast localStorage workspaces-cache (verified `parsed as Workspace[]` at workspaceStore.ts:103).

### Q2 — Conversation tile anatomy

Chat is the tile's face (unanimous competitor pattern; AgentChatPane already mounts anywhere). COMPOSITION (ruled for Bravo): ConversationTile.tsx (~140 LOC) wraps the UNFORKED AgentChatPane, which gains exactly two additive props — frame: "standalone"|"tile" and keyboardScopeActive — instead of Alpha's AgentChatBody+PaneHeaderShell extraction. Rationale: the smallest possible diff in exactly the phase where the protected keep-list stack (queued-send, fork-and-resend, ReviewBar) first survives multi-instance mounting; Alpha itself scored this a genuine tradeoff. The shared-header-grammar extraction is deferred to a post-retirement refactor, with an interim visual-parity requirement (grip, color dot, title, status pill, zoom in the same positions as terminal tiles). In frame="tile", AgentChatPane's existing 33px header doubles as chrome: MosaicWindowContext.connectDragSource grip, double-click zoom, zoom button; X removes the PANE ONLY (Bravo conceded close-as-archive conflated layout with lifecycle — the conversation survives as an unplaced fleet row; Archive is an explicit overflow action). WorkspaceMosaicContainer.renderTile gains one branch on pane.kind. KEYBOARD SAFETY (non-negotiable): ReviewBar's document-level Y/N keydown (verified at ReviewBar.tsx:71-73) arms only when keyboardScopeActive, driven by layoutStore.activePaneId (verified as the existing mosaic focus mechanism; the tile sets it on pointer-down as TerminalPane does) — with a dual-mode rule: no pane context → armed as today, so standalone AgentsView behavior is untouched. Escape layering is condition-based (Alpha's version, which Bravo conceded is more robust than defaultPrevented ordering): comment composer first, then ReviewSurface close, and the mosaic zoom-exit no-ops while reviewStore.open. REVIEW: ReviewSurface (699 LOC) NEVER renders at raw tile width — opening review auto-zooms via the existing setZoomedPane CSS-maximize (siblings visibility:hidden, nothing remounts, PTY/P0-2 law), with Alpha's autoZoomedBy bookkeeping so closing review un-zooms only if review caused the zoom; both teams rejected the truncated file-list review as a blind-accept hazard. RESPONSIVE (ruled hybrid — both original justifications were partly false): raw CSS @container rules handle all visual collapse (no Tailwind plugin needed — Alpha's plugin objection was irrelevant to raw CSS, and its "ollama polling" claim was false: useOllamaModels is a one-shot gated fetch); mounting economy comes from existing JS state, not a ResizeObserver — the always-visible narrow set is three cheap per-slice subscribers (AgentModeChip for safety posture, the Changes diffstat chip as the review entry, the amber approval badge), while ModelSelector/ContextUsageRing/SSH mount lazily only when the overflow menu opens or the tile is zoomed. Composer pins at tile bottom; agentDraftStore already keys drafts per-conversation, so N tiles get independent drafts/queued-send free. First-run draft tile (Alpha's flow, which Bravo credited): sparkle avatar + "Describe the task to start" + composer footer chips for model/mode/worktree that fold into the header after first send — no pre-creation modal. States: conversation is created in agentTaskStore BEFORE pane insertion (no half-born tile); loading renders the header immediately from the session record; missing-conversation shows the fallback + Remove-tile; failed turns show the red pill + retryLastTurn; aria-live gated to the focused tile. STREAMING: ships on the landed rAF streamCoalescer + zustand referential isolation + MessageList lazy rows, behind Alpha's numeric gate — 4 concurrent streams in a 2x2 mosaic hold p95 frame <16ms — with Bravo's measurable fallback: non-focused streaming tiles coalesce to 4Hz batched flushes via the injectable ScheduleFrame scheduler (focused tile stays per-frame). Watch-many-all-live remains the default posture.

### Q3 — Fleet layer (sidebar, needs-you, standalone sessions)

One list, one unit: FleetSidebar replaces WorkspaceSidebar, built from AgentSidebar's strictly-richer machinery (needs-you pseudo-group, status filter chips, /-search with message scan, pin, archive, relative time, projectLabels rename — projectLabels moves to a shared sidebar-prefs store); AgentSidebar dies with AgentsView at retirement. The row unit is the workspace; a new pure selector src/lib/sessionStatus.ts computes the rollup (max severity across member tiles) and is the SINGLE status truth also driving the tab-strip dot and RunningAgentsChip. Row anatomy (two lines): line 1 = rollup icon · name · relative time; line 2 = tile chips in agent colors ("Claude · Codex ×2 · Terminal") — OMITTED for single-tile rows, which render like today's conversation rows, so post-cutover the sidebar reads like the old Agents sidebar reorganized under project groups. PTY tiles only ever contribute working/idle — no fake PTY done states. NEEDS YOU is the pinned pseudo-group with amber count; clicking activates the workspace AND focuses+flashes the offending pane via workspaceStore.focusPaneRequest — never auto-zoom, never rearrange (both teams agreed); multi-tile rows carry per-chip amber dots. STANDALONE CONVERSATIONS (the headline contest, resolved by mutual concession into one mechanism): NO bulk migration — Alpha withdrew one-shot wrapping after Bravo's verified render-model attack (WorkspaceView.tsx:52/98/240-244: every active workspace is a header TAB and stays permanently MOUNTED behind display:none — wrapping 200 conversations means 200 tabs and 200 mounted chat panes). Instead, sessionIndex synthesizes virtual rows for every unplaced, non-archived, non-flight conversation, and OPEN IS A MATERIALIZING MUTATION (Bravo's conceded fix to its own view-path hole): one shared sessionGlue.openSession(ref) — used by sidebar click, needs-you click, and the retirement redirect shim — idempotently materializes a real workspace with Alpha's identity spec (deterministic id ws-wrap-<convId>, origin:"conversation", title live-follows the conversation's auto-title until first manual rename, then freezes) before setActiveWorkspace. WorkspaceView never renders synthetic records; no dual render path exists. New launches create real origin:"conversation" workspaces via launchConversation.ts. Archived unwrapped conversations appear as first-class rows under the Archived filter (unarchiving materializes a fresh wrapper) — nobody is stranded when AgentsView is deleted. No global inbox, no pseudo-workspace second code path (both teams agreed; zero competitor precedent). ARCHIVE lifecycle: archiving kills member PTYs (on archive, never on switch), archives member conversations, keeps transcripts; worktree cleanup follows the ruled policy (see q5); deleting a workspace DETACHES conversations, never destroys transcripts. sweepAutoArchive relocates from AgentsView's hourly mount-effect interval (verified AgentsView.tsx:100-101) to an App-shell effect at retirement. MOUNTED-COST GATE (pricing Bravo's tab-strip finding): 20 materialized conversation-only workspaces behind display:none must hold near-zero idle CPU with bounded listener count; the named fallback is mount-on-activation for workspaces containing ZERO PTY panes (safe — conversation state lives in the store, not the DOM; the PTY keep-all-mounted pattern itself is never modified).

### Q4 — One add-agent flow

One entry point, two anchors, one component: AddAgentPicker replaces the flat inline dropdown in WorkspaceView's header (same anchor) and backs the FleetSidebar's "New session" CTA (with a project picker) and the workspace zero-state (rendered inline, centered — first agent and Nth agent are one flow). It is a single searchable popover (reusing the Dropdown-searchable machinery ProviderPicker already uses) with ONE filterable list under two labeled section headers in capability language, never transport language: "Chat agents" FIRST (the new default face, per the market finding) — flattened API providers (Claude OAuth, Claude API, Codex ChatGPT, OpenAI, OpenRouter, MiniMax, Ollama) with color dot · name · default-model subtext · AuthBadge with the inline Log-in affordance lifted from ProviderPicker; then "Terminals" — the six CLI slots (Claude Code, Codex CLI, Gemini CLI, OpenCode, PacketCode, Terminal) with agent-color dot · name · installed-gating (existing isAgentInstalledForWorkspace + INSTALL_HINTS tooltips) and SSH awareness unchanged. The same vendor legitimately appears in both sections; section headers disambiguate search hits ("cla" → Claude under Chat agents, Claude Code under Terminals). The merged catalog is a thin static read-layer registry joining lib/api-models.ts and src/agents/\* under capability flags ({face, supportsApprovals, supportsSsh, models[]}) — killing the duplicate-catalog debt without touching either source of truth. SELECTION: a Terminal row adds a pane instantly (today's zero-friction behavior). A Chat row adds a DRAFT conversation tile — Alpha's flow, which Bravo explicitly credited over its own chevron drill-down: the picker answers WHO, the tile answers HOW, with model/mode/worktree as chips in the first-run composer footer (CC Desktop and Zed both put model at the composer) that fold into the header chip after first send; no pre-creation modal. Mode pickers are capability-FILTERED per runtime (ruled for Bravo, Alpha conceded): PermissionMode is auto|ask_for_risky|allow_all|deny_all (verified agent-conversation.ts:50 — there is no "Manual" mode to disable) and the Codex exec adapter cannot service ANY approval round-trip (verified agent-sidecar/src/providers/openai-codex.ts — every mode maps to sandbox+never; the -a on-request flow "can't work here"), so the Codex chat row shows ONLY honorable postures, relabeled in sandbox vocabulary (Read-only / Workspace-write / Full access), with the true posture chip in the tile header. Remote: a conversation added in a remote workspace auto-inherits SSH from workspace.serverId as conversation.sshTarget. Templates stay a creation-time, workspace-scoped concept behind a single "Workspace templates…" footer row opening the existing flow. Explicitly rejected by both teams: separate Add-CLI/Add-conversation buttons, and any runtime-first wizard.

### Q5 — Endings (commit, worktree lifecycle, Codex honesty)

ONE ending for both tile kinds: the existing GitDashboard slide-out (verified: takes bare {projectPath, workspaceId?, serverId?}; mounts only in WorkspaceView and FlightsView today) becomes FOCUSED-PANE-SCOPED — when the focused tile is a conversation in a worktree, the panel targets worktree.worktreePath (branch pkt/<convId>) with a header scope switcher back to workspace root. The conversation reaches it via a "Finish → Commit…" CTA added to the protected, unmoved ReviewBar when a session goes done/idle with reviewed changes. Full loop: stream → ReviewSurface (auto-zoomed) → Finish → stage/commit → Land → cleanup. Rejected by both teams: per-tile embedded git panels and a separate commit modal (a second ending IS the duplicated-subsystem debt being retired). WORKTREE LIFECYCLE — the unlandable-work fix, on verified foundations (no local merge exists anywhere in src-tauri — only github_merge_pr; removeConversationWorktree at tauri.ts:611 has ZERO callers; remove_local_worktree is `git worktree remove --force` and leaks the pkt/ branch): a WorktreeLifecycleBar inside GitDashboard with four actions. (1) Merge back — NET-NEW Rust command merge_conversation_branch(projectPath, branch, squash=true default) gated on the existing git_safety_check clean-root guard; conflicts surface in the existing feedback slot and leave both the worktree AND the user's root checkout intact; on success it deletes pkt/<convId> with -D (squash leaves no ancestry for -d — Alpha's conceded-then-specified branch-fate rule), removes the dir, and flips worktree.state→landed. (2) Create PR — publishBranchAsPr extracted behavior-preserving from asyncFlightStore.publishAttemptAsDraftPr into src/lib/gitPublish.ts (gitPushBranch→githubCreatePr), shared by flights and sessions, RECORDING the PR number (it feeds the cleanup predicate); shared shapes live in lib/worktreeLifecycle.ts. (3) Discard — first-ever wiring of removeConversationWorktree + flag-gated branch delete behind confirm; every non-Discard removal path dirty-checks first (Bravo's sharper safety spec). (4) Keep for later — worktree retained with a visible "worktree pending" chip. Legacy worktrees: read-layer derivation only, baseBranch unknown → explicit base picker defaulting to the repo default branch, ahead-counts labeled approximate. CLEANUP-ON-ARCHIVE (moderator ruling for Bravo's policy over Alpha's prompt): never / only-when-safe [default] / always, with the predicate specified — worktree clean AND (ancestry-merged OR recorded-PR-reports-merged OR zero commits ahead of base); everything else conservatively Keeps with the chip; auto-archive always Keeps. Deciding evidence: sweepAutoArchive is an hourly background interval (AgentsView.tsx:101) that structurally CANNOT prompt, so the Keep+chip machinery is mandatory regardless — Alpha's modal would be a redundant second mechanism that fires as an interrupt during bulk archives, and its squash-merge objection is answered by the recorded-PR and zero-ahead predicate arms. One amendment: an EXPLICIT archive of a workspace with unlanded work raises a non-blocking notification-layer toast with a "Review worktree" action — context-moment discoverability without a modal or a second codepath. SSH sessions: Land disabled with the existing remote-read-only message until remote git write ships. BLIND-COMMIT FIX (standalone, Phase 1): GitDashboard file rows become clickable into a diff view reusing the keep-list DiffRows/hunkDiff machinery. CODEX HONESTY ships at the catalog/chip layer as ruled in q4; the sidecar/adapter rewrite (codex proto/JSON-stdin) is explicitly out of scope — the stdin route was already tried and reverted (commit baa8be1).

### Q7 — Roadmap fit (api-agent:\* contract, Flight Deck, Remote Agents)

Everything sits ABOVE the frozen api-agent contract; the platform does not move, only the front door. PINNED BY TEST, not convention: new sessionContract.test.ts (Bravo's contribution, adopted wholesale, landing Phase 1 and gating EVERY phase) asserts createApiConversation's options — explicitId and skipBackendStart, the exact surface Flight Deck drives — the sessionId==conversationId invariant, hydration round-trip including conversation.worktree and legacy-key stripping (the stale workspaceId strip at agentConversationPersistence.ts:23/151 gets a named test so any future weakening of the no-placement rule fails CI rather than colliding with on-disk history), and canonicalizeAgentCli aliasing. The api-agent:{kind}:{sessionId} event vocabulary gets zero renames and zero additions; listeners stay installed per-conversation at the store layer with no UI dependence; startApiAgentSession gains no parameters — and its existing `workspace` parameter, which means local-vs-SSH EXECUTION context (the R0 contract), is explicitly named and firewalled against the UI-workspace concept (Bravo's catch, verified at api_agent.rs) so R0's vocabulary never collides with placement. THREE STRUCTURAL GUARANTEES: (1) sessionIndex is a deletable read-only projection — removing it cannot touch the engine; (2) reference direction is pane→conversationId only, enforced by agentWorkspaceDecoupling.test.ts plus the new eslint no-restricted-imports rule on sessionGlue, so a conversation WITHOUT a tile is a first-class citizen — which is precisely Remote Agents R0's shape: a remotely-driven session is just a conversation with no pane until someone opens one, at which point openSession materializes a workspace exactly as for any legacy conversation; (3) the flight-attempt exclusion is a READ-LAYER lookup over flight attempt sessionIds — no engine flag, no hidden field — so Flight Deck's attach-by-explicitId flow remains untouched proof the engine runs headless. Flight Deck specifically: publishAttemptAsDraftPr consumers keep passing after the gitPublish.ts extraction (gated by its existing tests in Phase 2), conversation.worktree is additive and AttemptTarget-isomorphic so lib/worktreeLifecycle.ts serves both owners without flights ever reading the new field, and attempt conversations never appear in the fleet sidebar. The deliberate share flows the OTHER way: the endings layer (gitPublish, worktreeLifecycle) becomes a lib both flights and sessions call, so R0 remote sessions inherit Create-PR for free once remote git write exists. Net: everything Flight Deck and Remote Agents R0 compile against today compiles unchanged, and breaking it turns CI red inside the increment that broke it.

### Standalone conversations: bulk one-shot wrapper migration vs virtual rows with lazy materialization

- **Alpha:** Original: one-shot idempotent migration wrapping every non-archived conversation in a real ws-wrap-<convId> workspace; rejected virtual rows as a permanent second code path. Withdrawn in defense after Bravo's render-model attack.

WorkspaceView never renders synthetic records — no dual render path.

### Pane discriminant: overload agentId with a "conversation" value vs a new kind field

- **Alpha:** WorkspaceAgentSlot gains "conversation"; agentId is the sole existing discriminant so extending it is the smallest schema change. Withdrawn in defense.
- **Bravo:** kind?: "pty"|"conversation" with #[serde(default)]; agentId semantics stay intact; an old binary drops an unknown FIELD (inert) rather than misreading a known field's VALUE (active).
- **Ruling:** Bravo wins, completed by Alpha. Verified: "conversation" as an agentId would leak into workspace.agents[] (workspaceStore.ts:353/374), agentCounts header badges (WorkspaceView.tsx:79-84), and override record keys, and the From<String> catch-all (api/mod.rs, `_ => Self::Terminal`) would turn the sentinel into a live shell-spawning pane on old binaries. But Bravo's spec left agent_id's persisted value for conversation panes undefined — core WorkspacePane.agent_id is a non-optional String, so an unknown value hits the same Terminal coercion. Final: kind is the discriminant; conversation panes persist agent_id:"terminal" as a documented inert carrier; an audited checklist moves every agentId-keyed site onto kind.

### Downgrade safety: inert carrier + self-heal vs lazy schema-version stamp causing old-binary refusal

- **Alpha:** Revised: conversation panes persist agent_id:"terminal" so an old binary renders a benign shell tile, never corrupts; the reconciliation sweep re-pairs the orphaned conversation on re-upgrade. No refusal mechanism.
- **Bravo:** Revised: stamp a schema version on the workspace file when the first conversation pane is written so old binaries REFUSE (recoverable) rather than silently coerce and strip conversation_id on re-save.
- **Ruling:** Alpha wins, on storage-granularity evidence Bravo's proposal didn't survive: workspaces persist inside the single monolithic state.v1.json (storage.rs:67 STATE_FILENAME; :102/:110 PersistedState{version, workspaces,...}) and version is an optimistic-concurrency counter bumped on every save with no schema gate on load — there is no per-workspace file to stamp, so any refusal marker locks a downgraded binary out of the user's ENTIRE persisted state (every workspace, PTY layouts included) the moment one user opens one conversation tile. A benign terminal tile + permanent self-heal (conversation files untouched; sweep re-surfaces the unplaced row) is strictly less destructive. Bravo's demand that gates exercise the old-binary RE-SAVE path (not just parse) is adopted as a Phase-1 gate.
