# Sprints

Last updated: 2026-06-15

This is the rolling near-term sprint plan agreed after the Mission→Flight rename
audit. Sprints here are intentionally not dated: they are sequenced by dependency,
not calendar. As each ships, fold its closed items into [`../CHANGELOG.md`](../CHANGELOG.md)
and move residual open work to [`../backlog.md`](../backlog.md).

Trust anchors before working any item:

- [`../backlog.md`](../backlog.md) — live task register.
- [`../ROADMAP.md`](../ROADMAP.md) — release priorities (post-rename, v0.9.4 state).
- [`README.md`](./README.md) — planning index.
- [`flight-planner-reliability-continuity-pack.md`](./flight-planner-reliability-continuity-pack.md) — Flight Planner reliability contract.

> **Environment note.** This working tree is WSL2 over a Windows project.
> `node_modules` were installed on Windows, so Linux-native binaries are absent:
> Vitest (rollup) and the live sidecar smokes (Claude Agent SDK Linux CLI, codex
> CLI) cannot run in WSL2 — that is environmental, not a code defect. The Windows
> host is the gate-execution environment for those gates; the Rust toolchain runs
> via Windows MSVC `cargo.exe`. Items below that say "re-run on a Windows host"
> mean exactly this.

> **Intentional back-compat (do not "fix").** The Mission→Flight rename
> deliberately preserves: 5 Rust `#[serde(alias = "missionId")]` shims on
> persisted structs; the `issueStore.ts` and `goalStore.ts` legacy `missionId`
> read shims; and the on-disk journal directory literal `~/.packetade/missions/`
> (`join("missions")`). These are persistence/back-compat surfaces, not leftover
> rename misses. Any sweep that touches them must leave them in place.
