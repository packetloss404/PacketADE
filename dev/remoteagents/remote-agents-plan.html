Implementation brief / 2026-05-26

Use every PacketADE agent from your phone.

Remote Agents makes the desktop app an online agent host. The phone signs into Packet Cloud, controls trusted desktops through a secure relay, and uses the exact providers, models, profiles, workspaces, MCP setup, and approvals already configured in PacketADE.

Locked direction

The plan in eight decisions

These are the choices the implementation team should treat as fixed unless the owner explicitly reopens them.

Cloud relay

Phone connects through Packet Cloud, not local network discovery.

Account sign-in

Primary UX is passkey/magic-link Packet sign-in. QR is optional later.

Desktop host

PacketADE desktop runs agents, tools, keyring access, OAuth, MCP, and files.

PWA first

Build remote.packetade.app before native iOS/TestFlight.

WebSockets

Foreground bidirectional control uses WebSockets; Web Push wakes users.

API agents only

No raw PTY, deploy controls, full mobile IDE, or remote shell in MVP.

Cloudflare stack

Workers, Durable Objects, D1, R2, Queues, and analytics are the default.

Narrow protocol

Every remote action is an explicit audited command. No generic invoke bridge.

Cloud can see

Account, host, device, channel, type, timestamps, size, sequence, audit metadata.

Cloud cannot see

Prompts, code, tool arguments, diffs, OAuth, API keys, MCP secrets, local env.

Desktop validates

Trusted device, capability scope, provider/model, workspace, pending approvals.

Scope

MVP: remote-control the API-agent loop

The first release should feel complete for mobile chat and approvals while keeping the dangerous surfaces out.

Include

  • +Packet account sign-in and desktop device approval.
  • +Host, workspace, provider, model, and profile discovery.
  • +Start, continue, send, cancel, retry, and set model for API-agent conversations.
  • +Stream existing api-agent:* events to the phone.
  • +Approve once, deny, apply/reject edits, and cancel pending tools from mobile.
  • +Push notifications for approvals, completion, and failure.

Exclude

  • -Raw PTY control or arbitrary shell submission.
  • -Cloud-stored provider secrets or provider calls from cloud.
  • -Full file browser, full IDE, deploy controls, or team/org sharing.
  • -Native iOS/TestFlight before PWA proof.
  • -Mobile allow_always until step-up auth exists.
  • -WebRTC/LAN direct path in v1.

Conversation cards

Text, thinking collapsed by default, tool cards, permission cards, pending edit summaries, plan blocks, token totals, done/error states.

Reconnect model

PWA stores cursors in IndexedDB, reconnects over WebSocket, replays encrypted events, and falls back to a desktop snapshot.

Push stance

Use Web Push to wake the user for approvals and completion. Do not rely on background sockets, especially on iOS.

Native later

After PWA beta, evaluate TestFlight/iOS for APNs, Keychain, stronger background behavior, and better device trust UX.

Delivery plan

Seven checkpoints to beta

Sprints are intentionally checkpoint-based so parallel agents can merge by working surface, not calendar optimism.

Sprint 0

Foundations and decisions

Protocol schemas, repo layout, feature flag, Worker/PWA skeletons, auth decision, encryption gate.

Checkpoint: shared protocol builds; desktop compiles with remote flag off.
Sprint 1

Relay and host presence

Worker routes, HostRoomDO, D1 schema, desktop outbound WebSocket, PWA host list.

Checkpoint: trusted PWA sees desktop online; revoked device cannot subscribe.
Sprint 2

Provider/workspace/profile snapshots

Desktop exports what it can run: providers, models, auth status, profiles, workspaces.

Checkpoint: PWA can choose a real workspace and ready provider without secrets in logs.
Sprint 3

Backend conversation service

Move enough lifecycle into Rust so phone-created conversations are first-class on desktop.

Checkpoint: start on phone, see stream on phone and desktop, cancel from phone.
Sprint 4

Mobile conversation UX

Needs Me, Active, New, History, Hosts, event cards, approvals, reconnect, IndexedDB cursors.

Checkpoint: lock phone, reopen, resume stream; approval unblocks desktop agent.
Sprint 5

Push, audit, security hardening

Web Push, audit rows, revocation, origin validation, rate limits, E2EE gate.

Checkpoint: new phone needs desktop approval; revocation cuts active socket.
Sprint 6

Beta polish and release

Load test, browser matrix, failure runbook, staged deploy, private beta allowlist.

Checkpoint: 30-minute remote session with disconnects passes on iOS and Android.
North-star acceptance test An iPhone PWA starts a real PacketADE API-agent conversation against D:\projects\PacketADE, streams within 2 seconds of desktop events, approves one risky tool, completes or cancels the run, and the same conversation opens on desktop.

Security gates

Treat this like high-risk infrastructure

A phone can approve an agent that writes files or runs commands. The plan keeps cloud identity, device trust, desktop policy, and encrypted payloads separate.

Auth

Passkey first, magic-link fallback, desktop PKCE via system browser, short-lived access tokens, rotating refresh tokens.

Trust

Same-account devices still need desktop approval. Trust grants bind account, host, device, keys, scope, and signature.

Encryption

Internal dev may use plaintext. External beta requires encrypted agent, approval, file, and control payloads.

Gate Must pass Owner lane
Provider secrets No API keys, OAuth files, MCP env, SSH keys, or raw local env in cloud/PWA logs. Security + QA
Authorization Object-level checks for every account, host, device, conversation, and command. Cloud + Security
Revocation Revoked active device loses WebSocket within 5 seconds and desktop rejects frames. Relay + Desktop
Mobile approval MVP allows allow_once or deny only; mobile allow_always is rejected. PWA + Desktop
Audit Every mutating command produces redacted local and cloud metadata audit rows. Desktop + Cloud
Testing

Proof before beta

The beta exit criteria are about correctness, authorization, and mobile reliability.

Protocol

Schema tests, version rejection, payload caps, idempotency keys, encrypted-required channels.

Relay

Connect/disconnect, replay, duplicate command ignore, slow-client coalescing, revoked socket close.

Desktop

Provider snapshot redaction, remote command validation, conversation persistence, approval routing.

PWA

Mobile Playwright flow for sign-in, host selection, stream, approval, cancel, reconnect.

Manual mobile

iPhone Home Screen PWA, iPhone browser tab, Android installed PWA, Android browser tab.

Acceptance run

30-minute remote session with disconnects; stream and approval under 2 seconds after desktop event.

Open decisions

Decide early, document immediately

These choices should not block Sprint 1 presence work, but they must be resolved before private beta.

Auth provider

Use managed passkey/magic-link auth, build it, or use dev auth for Sprint 1 only.

Encryption timing

Plaintext is internal-smoke only. External beta requires E2EE frames and test vectors.

Code location

Default to remoteagents/shared, remoteagents/relay-worker, and remoteagents/pwa.

Persistence shape

Use minimal Rust remote snapshots now; move full conversation schema backend-native later.

Native iOS

Revisit after PWA beta, with APNs, Keychain, backgrounding, and TestFlight needs in view.

Security conflict

Where docs disagree, the stricter rule wins: mobile MVP can approve once or deny only.
